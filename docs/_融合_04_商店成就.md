### 1.2 成就设计（`achievements.gd` 276行）

**架构**：Achievements Autoload 单例，零侵入设计——`_process` 每 0.5s 轮询游戏状态 + 连接现有信号，不修改任何玩法脚本。JSON 存档（`user://achievements.json`，v2 schema），Toast 通知滑入动画。

**8 成就明细**：

| 成就ID | 名称 | 条件 | 图标 |
|---|---|---|---|
| `first_kill` | 初阵 | 击杀第一只丧尸（kills_total ≥ 1） | 💀 |
| `hundred_kills` | 百人斩 | 累计击杀 100 只（kills_total ≥ 100） | ⚔ |
| `all_weapons` | 武器收藏家 | 使用过全部 4 种武器 | 🔫 |
| `clear_ch1` | 黄昏町制霸 | 通关第一章（current_wave ≥ 5） | 🏆 |
| `flawless` | 无伤过关 | 一波次中不受任何伤害 | 🛡 |
| `special_x10` | 热血魂爆发 | 累计释放必杀 10 次（specials_used ≥ 10） | 🔥 |
| `capture_x5` | 援护收藏家 | 收服 5 只援护丧尸（captures_total ≥ 5） | 🤝 |
| `vehicle_squash` | 马路杀手 | 累计驾驶载具 30 秒 | 🚗 |

**检测机制**：
- 轮询：`_poll_stats()` 每 0.5s 读取 game 节点的 `kills`/`wave`，遍历 players 收集武器使用/HP变化/收服数
- 信号连接：`p.special_used.connect(_on_special_used)` 检测必杀释放
- 波次推进检测：`_prev_wave` 对比，上一波零伤害则解锁 `flawless`
- 解锁后：emit `achievement_unlocked` 信号 + 保存 JSON + 显示 Toast

## 三、商店扩展注入方案

### 3.1 设计思路

原版已有 **7 种业态**（STORE/EQUIP/COOK/RECYCLE/SENTOU/CAFE/MACHINE）和完整的商品/购买记录系统。Godot 的 4 分类（弹药/装备/食物/技能书）不需要新增业态，而是**映射到现有业态框架内**：

| Godot 分类 | 映射到原版业态 | 说明 |
|---|---|---|
| ammo（弹药） | STORE（一般商店） | 消耗品，`mstConsumableDataData.eenumsumableitem` 对应弹药类 |
| gear（装备） | EQUIP（装备店） | 装备品，`mstEquipDataData` 对应 |
| food（食物） | COOK（料理店） | 回复类消耗品，`mstConsumableDataData.effectid` = 回血 |
| skill（技能书） | STORE（一般商店）+ 特殊效果 | 消耗品，`effectid` = 学技能，使用后触发 `LearnSpWaza` |

**核心策略**：不新增 SHOP_TYPE，而是在现有 STORE/COOK/EQUIP 业态下，通过 `mstConsumableDataData` 和 `mstShopAssortData` 新增商品行来实现 Godot 风格的商品。

### 3.2 必杀书商品实现（核心特色）

**链路**：
```
mstConsumableDataData 新增行（必杀书）
  → effectid = 学技能效果ID
  → value1 = EnumWazaID 值（要习得的必杀技）
  → 玩家在商店购买 → 获得该消耗品
  → 玩家在背包使用 → CItemUseControl.UseItem()
    → 检测 effectid == 学技能 → 调用 CStorySaveData.LearnSpWaza(value1)
    → CSpecialMoveInfo.AddLearnedWazaListt(wazaId)
    → 成就进度更新（UpdateSpWazaAchievementProgress）
```

### 3.3 商店 UI 扩展

原版已有 `CShopItemList` / `CShopEquipList` / `CBulkBuyDialog` / `CShopPreviewWindow`，不需要新增 UI 类。扩展方式：

1. **分类页签**：原版 STORE 业态已有商品列表，必杀书作为特殊消耗品出现在 STORE 列表中
2. **"已拥有"标记**：通过 `CStorySaveData.LearnSpWaza` 查询该必杀技是否已习得，已习历时按钮置灰
3. **预览窗口**：`CShopPreviewWindow` 已有，扩展显示必杀技名称/描述（`mstWazaMenuData.Waza_Name/Waza_Description_M`）

## 四、成就扩展注入方案

### 4.1 原版成就系统映射

原版已有 **35 个具名成就**（`NKSP.Achievements` 枚举），Godot 的 8 成就可以直接映射到原版成就框架：

| Godot 成就 | 原版映射 | 映射说明 |
|---|---|---|
| `first_kill`（初阵） | 无直接对应 → 新增 ID_31 | 首次击杀，原版无此成就 |
| `hundred_kills`（百人斩） | `DEFEAT_BONUS_ENEMY` 类似 | 累计击杀数，原版有 Bonus Enemy 击败成就 |
| `all_weapons`（武器收藏家） | `OBTAIN_UNIQUE_ITEM` 类似 | 使用全部武器，原版有独特物品获取成就 |
| `clear_ch1`（黄昏町制霸） | `CLEAR_STORY_1` | 第一章通关，直接对应 |
| `flawless`（无伤过关） | 无直接对应 → 新增 ID_32 | 无伤害通关，原版无此成就 |
| `special_x10`（热血魂爆发） | `LEARN_SPECIALS_5` 类似 | 必杀使用次数，原版有习得数量成就 |
| `capture_x5`（援护收藏家） | 无直接对应 → 新增 ID_33 | 收服援护，原版无此成就 |
| `vehicle_squash`（马路杀手） | 无直接对应 → 新增 ID_34 | 载具撞击，原版无此成就 |

**扩展策略**：原版 ACHIEVE_ID 已有 ID_00~ID_30（32项），MAX 为哨兵。新增成就使用 **ID_31~ID_34**（4个新成就），其余4个映射到现有成就。

### 7.5 关键风险与缓解

1. **effectid 数值不确定**：mstConsumableDataData.effectid 的"学技能"效果ID是编译在 ScriptableObject 资源中的，DLL 元数据不包含具体数值。**缓解**：通过 strings 扫描 DLL 中 "effectid" 附近的数字常量，或从游戏数据目录提取 .asset 文件确认。

2. **EnumConsumableItem 84项排查**：需确认原版是否已有"技能书"类消耗品，避免 ID 冲突。**缓解**：遍历 84 个枚举值对应的 mstConsumableDataData 行，检查 effectid 分布。

3. **AchievementsCollector 异步队列**：Unlock/Progress 方法内部有 QueueUnlock/QueueProgress 协程，直接调用可能需要主线程上下文。**缓解**：使用 AccessTools 调用公开方法，或在主线程 Update 中触发。

4. **Steam 成就 ID 映射**：新增成就需要在 Steamworks 后台配置对应的 Steam Achievement ID，否则 Unlock 后不会同步到 Steam。**缓解**：mod 阶段可仅做本地成就，Steam 对接后续按需添加。
