### 关键技术发现

1. **原版已有大量可复用框架**：AI 状态机（CAiStateMachine）、阵营系统（AI_TRIBE=OPPOSITION/COMPANION）、状态效果管理器（CStatusEffectManager）、伤害计算器（CDamageCalculator 含 Buff_Mul/Buff_Add）、商店7业态、成就32项——这些都不需要从零新建，只需扩展数据表 + Harmony patch。

2. **"打残收服"可通过原生阵营切换实现**：`CActorNpcControl.m_AITribe` 有 get/set，将敌人从 OPPOSITION 改为 COMPANION 即可变为友军，原版 opponentList 自动识别。

3. **必杀书完整链路已确认**：`mstConsumableDataData.effectid` → `CItemUseControl.UseItem` → `CStorySaveData.LearnSpWaza` → `CSpecialMoveInfo.AddLearnedWazaList`，5本角色必杀书可通过新增消耗品数据行实现。

4. **载具系统原版完全没有**：2051个类型中无任何 Vehicle/Car/Drive 相关类，EnumAction 839个动作中无骑乘动作，需全新增 MonoBehaviour 组件。

5. **枚举不能运行时扩展**：EnumWeaponItem（41种武器）、EnumWazaID（203种必杀）等枚举编译在 DLL 中，Harmony 无法新增枚举值，需用常量+数据表替代方案。

### 环境限制与方案选择

**当前环境**：Python 3.12 + dnfile 0.18.0（只读 .NET 元数据解析），无 dnSpy / ILSpy / monodis / dotnet SDK / mono C# 编译器。

**因此采用 Harmony mod 注入方案**而非直接修改 DLL：
- 不修改原 DLL 方法体，通过 Harmony 库在运行时对目标方法做 Prefix / Postfix / Transpiler 补丁
- 新增类（枪械、载具、可破坏物等）编译为独立 mod DLL，随游戏启动加载
- 数据表扩展通过修改 bundle 中的 ScriptableObject 资源（.asset）实现
- 原 DLL 保持不变，mod 可随时卸载

**实施前提**：需在有 Visual Studio / dotnet SDK 的 Windows 环境中编译 mod DLL（引用游戏的 Assembly-CSharp.dll + UnityEngine.dll + 0Harmony.dll），本文档提供全部 C# 参考代码。

## 技术方法论

### 1. dnfile 元数据解析
所有 Unity DLL 的类名、字段名、方法签名、枚举值均通过 `dnfile` 直接解析 .NET 元数据表获得（2051个类型、20761个字段），证据等级为**确定**。方法内部逻辑（IL 指令）不可见，涉及方法语义的推断均在文档中标注"推断"。

### 2. Harmony 注入方式
| Patch 类型 | 用途 | 适用场景 |
|---|---|---|
| **Prefix** | 在原方法执行前拦截/替换 | 拦截武器攻击、注入枪械发射逻辑 |
| **Postfix** | 在原方法执行后追加逻辑 | 受击后追加buff结算、击杀后触发成就检测 |
| **Transpiler** | 修改原方法 IL 指令流 | 需深度修改伤害计算公式时 |
| **新增类** | 独立 MonoBehaviour / 工具类 | 枪械控制器、载具、可破坏物组件 |

### 3. 数据表扩展
游戏数值（HP、伤害、价格、掉落率等）存储在 ScriptableObject（.asset）中，经 Addressables 加载，不在 DLL 内。扩展方式：
- 用 Unity 打开工程或直接修改 bundle 中的 .asset 资源
- 新增武器行 → `mstWeaponDataData` + `mstAttackCollisionData` + `mstWeaponActionData`
- 新增商品行 → `mstConsumableDataData` + `mstShopAssortData`
- 新增敌人行 → `mstActorParamaterData` + `mstEnemyGroupData`

### 4. 实施步骤总览
1. 搭建 mod 开发环境（Windows + Visual Studio + 引用游戏 DLL + Harmony库）
2. 按本文档各章节的 C# 代码实现 mod 类和 Harmony patch
3. 修改 bundle 数据表，新增武器/商品/敌人/状态效果数据行
4. 制作所需美术资源（子弹预制体、载具模型、可破坏物模型、爆炸特效）
5. 编写 mod 加载器（BepInEx 或自定义启动器），将 mod DLL 放入游戏目录
6. 测试各系统功能，调整数值平衡

## 一、Godot 武器系统设计摘要

### 1.1 枪械（weapons.gd WEAPONS 表）

| 武器 key | 冷却(s) | 最大弹药 | 伤害 | 子弹速度 | 行为说明 |
|---|---|---|---|---|---|
| `pistol` | 0.25 | -1（无限） | 2 | 640 px/s | 默认副武器，手枪子弹黄色 |
| `machine_gun` | 0.08 | 120 | 2 | 900 px/s | 高射速，子弹青色 |
| `shotgun` | 0.60 | 24 | 1（每颗弹丸） | 560 px/s | 散射，子弹橙色 |
| `grenade` | 1.00 | 3 | 8 | 0（抛物线） | 手雷，落地后 1.5s 引信爆炸 |

### 1.2 近战（weapons.gd MELEE_WEAPONS 表）

| 武器 key | 基础伤害 | 耐久 | 范围倍率 | 击退倍率 | 可格挡 | 名称 |
|---|---|---|---|---|---|---|
| `iron_pipe` | 6 | 15 | 1.5 | 1.5 | false | 铁管 |
| `tire` | 4 | 20 | 1.2 | 2.0 | false | 轮胎 |
| `trash_lid` | 3 | 25 | 1.0 | 1.0 | true | 垃圾桶盖 |

> 近战武器每次命中 -1 耐久；格挡时受击伤害 ×0.5，每次格挡耗 2 耐久；耐久耗尽后武器消失。

### 1.3 子弹行为（bullet.gd）

- 继承 `Area2D`，直线飞行，`dir` 方向 + `speed` 速度
- 生命周期 `life = 2.0s`，超时自动销毁
- 命中任何带 `take_damage` 方法的节点即造成 `damage` 伤害并自毁
- 视觉颜色按武器区分（手枪黄/MG青/霰弹橙）

### 1.4 手雷行为（grenade.gd）

- 继承 `CharacterBody2D`，受重力（`GRAVITY = 980`）
- 投掷初速：X 方向 `THROW_X = 400`，向上 `THROW_UP = 300`
- 落地后启动引信 `FUSE_TIME = 1.5s`，期间闪烁警告
- 爆炸：`BLAST_RADIUS = 80` 范围内所有 `"zombies"` 组节点受 `BLAST_DAMAGE = 8` 伤害
- 视觉：快速放大的橙色色块 + 淡出

### 1.5 拾取逻辑（item_pickup.gd）

- 继承 `Area2D`，碰撞 mask = 1（仅检测玩家）
- 玩家进入触发区 → 发出 `item_picked(item_type)` 信号 → 自毁
- `item_type` 为字符串：`"ammo"` / `"first_aid"` / `"iron_pipe"` / `"tire"` / `"trash_lid"`
- 视觉：不同武器不同颜色色块图标

### 4.1 枪械武器类：子弹飞行 + 射速 + 弹药

> 对应 Godot `bullet.gd`。Unity 版已有 `CBulletItemControl`，这里用 Postfix 扩展它。

```csharp
using System.Collections.Generic;
using HarmonyLib;
using NK21;
using UnityEngine;

namespace HotBloodZombieMod
{
    /// <summary>
    /// 枪械开火控制器：挂在 ActorControl 上，管理冷却/弹药/生成子弹。
    /// 对应 Godot player.gd 里的开火逻辑。
    /// </summary>
    public class GunFireController : MonoBehaviour
    {
        public int currentWeaponId = NewWeaponID.NONE;
        public int currentAmmo = 0;
        private float _cooldownTimer = 0f;
        private ActorControl _actor;

        void Awake() { _actor = GetComponent<ActorControl>(); }

        void Update()
        {
            if (_cooldownTimer > 0f) _cooldownTimer -= Time.deltaTime;
            var def = WeaponRegistry.Get(currentWeaponId);
            if (def == null) return;

            // 推断：原游戏用 CInputControl.IsPressKey 检测按键
            // 这里用一个简化的开火输入 hook（实际需接 EnumKeyID）
            bool firePressed = Input.GetKeyDown(KeyCode.J); // 示例键位
            if (firePressed && _cooldownTimer <= 0f)
            {
                Fire(def);
            }
        }

        void Fire(WeaponDef def)
        {
            if (def.kind == WeaponKind.Grenade)
            {
                ThrowGrenade(def);
                return;
            }

            if (def.maxAmmo > 0 && currentAmmo <= 0) return; // 弹药耗尽

            _cooldownTimer = def.cooldown;
            if (def.maxAmmo > 0) currentAmmo--;

            switch (def.kind)
            {
                case WeaponKind.Pistol:
                    SpawnBullet(def, 0f); // 直线
                    break;
                case WeaponKind.MachineGun:
                    SpawnBullet(def, 0f);
                    break;
                case WeaponKind.Shotgun:
                    // 霰弹：5 颗散射（对应 Godot shotgun damage=1 每颗弹丸）
                    for (int i = -2; i <= 2; i++)
                        SpawnBullet(def, i * 8f); // 每颗偏差 8 度
                    break;
            }
        }

        /// <summary>
        /// 生成一颗子弹。调用原游戏 CItemManager.CreateBulletItemObject。
        /// 注意：CItemManager 无静态 Instance（dnfile 验证），是 MonoBehaviour。
        /// 推断：通过 FindObjectOfType<CItemManager>() 或场景单例访问。
        /// </summary>
        void SpawnBullet(WeaponDef def, float angleOffsetDeg)
        {
            // 推断：CItemManager 是场景中的 MonoBehaviour，无静态 Instance
            // 用 FindObjectOfType 获取（实际项目中可能有更好的单例访问方式）
            var itemManager = UnityEngine.Object.FindObjectOfType<CItemManager>();
            if (itemManager == null) return;

            // 推断：角色朝向通过 CObjectControl.m_Flip 获取（dnfile 验证 CObjectControl 有 m_Flip/m_FlipY）
            var objCtrl = _actor.GetComponent<CObjectControl>();
            Vector2 dir = (objCtrl != null && objCtrl.m_Flip) ? Vector2.left : Vector2.right;
            // 应用角度偏移
            float angle = Mathf.Atan2(dir.y, dir.x) + angleOffsetDeg * Mathf.Deg2Rad;
            Vector2 vel = new Vector2(Mathf.Cos(angle), Mathf.Sin(angle)) * def.bulletSpeed;

            // 推断：CreateBulletItemObject 需要位置/方向/伤害参数
            // 实际参数签名需用 dnfile 读 MethodDef Signature blob 确认
            itemManager.CreateBulletItemObject(); // 占位，具体参数需补
        }

        void ThrowGrenade(WeaponDef def)
        {
            // 手雷走投掷管线：CPickObjectControl.ThrowObject
            // 对应 Godot grenade.gd 的抛物线
            var pickCtrl = _actor.m_PickObjectControl;
            pickCtrl.ThrowObject(); // 推断调用现有投掷
        }
    }

    /// <summary>
    /// Postfix：CBulletItemControl.FixedUpdateRun —— 让枪械子弹走直线、不反弹。
    /// 对应 Godot bullet.gd 的 _physics_process：直线飞行 + 生命周期。
    /// </summary>
    [HarmonyPatch(typeof(CBulletItemControl), "FixedUpdateRun")]
    static class BulletStraightPatch
    {
        static void Postfix(CBulletItemControl __instance)
        {
            // 推断：原游戏子弹可能有反弹/重力逻辑。
            // 枪械子弹应走直线、受自身速度控制、不反弹。
            // 通过 m_NowBulletAction 判断是否为"飞行中"状态。
            // 这里仅作示意，实际需读 m_NowBulletAction 的枚举值。
            var objCtrl = __instance.GetComponent<CObjectControl>();
            if (objCtrl != null)
            {
                // 保持直线：不施加重力，速度方向不变
                objCtrl.m_Gravity = 0f; // 推断字段
            }
        }
    }
}
```

### 4.2 手雷类：抛物线 + 爆炸 AOE

> 对应 Godot `grenade.gd`。Unity 版已有 `Item_Throw_Arch` 抛物线类型和 `Explosion_Fire` 特效。

```csharp
using System.Collections.Generic;
using HarmonyLib;
using NK21;
using UnityEngine;

namespace HotBloodZombieMod
{
    /// <summary>
    /// 手雷爆炸器：挂在手雷物品对象上，落地引信倒计时，到期 AOE 伤害。
    /// 对应 Godot grenade.gd。
    /// </summary>
    public class GrenadeExplosion : MonoBehaviour
    {
        public float fuseTime = 1.5f;
        public float blastRadius = 80f;
        public int blastDamage = 8;
        public float gravity = 980f;

        private float _fuseTimer = 0f;
        private bool _fuseStarted = false;
        private bool _exploded = false;

        void FixedUpdate()
        {
            if (_exploded) return;

            // 未落地：抛物线运动（对应 Godot 的 velocity.y += GRAVITY*delta）
            if (!_fuseStarted)
            {
                // 推断：用 CObjectControl 的重力/速度
                var objCtrl = GetComponent<CObjectControl>();
                if (objCtrl != null && !IsGrounded(objCtrl))
                {
                    objCtrl.m_Gravity = gravity; // 推断字段
                }
                else
                {
                    _fuseStarted = true;
                    _fuseTimer = fuseTime;
                }
            }
            else
            {
                _fuseTimer -= Time.fixedDeltaTime;
                // 闪烁警告（视觉，用 SpriteRenderer 控制）
                var sr = GetComponent<SpriteRenderer>();
                if (sr != null)
                    sr.enabled = Mathf.PingPong(Time.time * 5f, 1f) > 0.5f;

                if (_fuseTimer <= 0f) Explode();
            }
        }

        bool IsGrounded(CObjectControl ctrl)
        {
            // 推断：用 GroundChecker 或碰撞检测判断落地
            // 简化：检查 m_MoveGround 字段（推断）
            return ctrl.m_MoveGround; // 推断
        }

        void Explode()
        {
            if (_exploded) return;
            _exploded = true;

            // 1. 播放爆炸特效（对应 Godot 的 Tween 放大色块）
```

## 六、风险与注意事项

### 6.1 高风险（必须额外资源/实验）

| # | 风险 | 说明 |
|---|---|---|
| 1 | **子弹预制体缺失** | `CItemManager.m_BulletItemPrefab` 指向游戏自带子弹预制体（对应 Makoto/必杀技子弹）。枪械需要新的子弹预制体（Sprite + Collider + Rigidbody）。**没有美术资源无法做出可视子弹**。最简方案：复用游戏现有子弹预制体，改颜色/速度。 |
| 2 | **Animator 状态机不支持"射击"动作** | 原游戏 839 个动作状态里没有"持枪站立/射击"动画。枪械武器只能复用 `SWeapon_Stand` + `SWeaponAttack_Stand`，视觉上是"拿着日用品挥"。**要真持枪射击需要新动画，工作量巨大**。 |
| 3 | **枚举传入非法值** | `mstWeaponDataData.eenumweaponitem` 类型是 `EnumWeaponItem`，传入 100 等不在枚举定义里的值。C# 枚举底层是 int，运行时不会抛异常，但游戏内查表（如 `Enum.IsDefined`）可能过滤掉。**需测试原游戏是否用 `Enum.IsDefined` 校验**。 |
| 4 | **方法签名未知** | `CItemManager.CreateBulletItemObject()`、`CPickObjectControl.ThrowObject()` 等方法的**参数签名**未从 dnfile Signature blob 解析。上面代码里的调用是推断。**实际 patch 时需用 dnfile 解析 MethodDef.Signature 拿到精确参数列表**。 |

### 6.2 中风险（可行但需调试）

| # | 风险 | 说明 |
|---|---|---|
| 5 | **伤害计算管线参数** | `CDamageCalculator.CalcDealtDamage()` 的参数（攻击者/防守者/攻击数据/伤害类型）未确认。需解析 Signature blob。 |
| 6 | **特效播放接口** | `EnumEffect.Explosion_Fire` 是特效 ID，但**如何播放特效**的接口类/方法未在本次查询中定位。需进一步搜索含 "Effect" 的播放类。 |

## 三、载具系统注入方案

### 3.1 总体判断

**原版无载具系统 → 全新增 MonoBehaviour 组件。**

不能通过扩展现有类实现，因为：
1. 没有 `Vehicle`/`Car`/`Bike` 等任何载具类型
2. `EnumAction`（839 个动作状态）中无骑乘/驾驶动作
3. `CActorNpcControl` 的移动/碰撞系统不支持"乘客"概念

### 3.2 载具组件架构设计

```
ModVehicle (新增 MonoBehaviour)
├── 挂载位置：场景中独立的 GameObject（不挂在 CActor 上）
├── 依赖系统：
│   ├── CObjectControl（物理移动/碰撞，复用其 Rigidbody2D）
│   ├── CInputControl（驾驶员输入转发）
│   ├── CAttackCollision（受击/攻击判定）
│   ├── CDamageCalculator（伤害计算）
│   └── EnumEffect（爆炸/火焰特效播放）
├── 状态：
│   ├── driver: CActorNpcControl（驾驶员引用，null 表示无人）
│   ├── durability: int（耐久度）
│   ├── cannonAmmo: int（主炮弹药）
│   ├── facing: int（朝向 1/-1）
│   └── invincibleTimer: float（无敌帧计时）
└── 核心方法：
    ├── EnterVehicle(CActorNpcControl driver)
    ├── ExitVehicle()
    ├── TakeDamage(int dmg)
    ├── FireVulcan()
    ├── FireCannon()
    └── Explode()
```

### 3.3 上下车与 CActor 的交互方案

**方案：不修改 CActor 内部状态机，而是通过外部组件"覆盖"输入。**

```
玩家站在载具附近 → 按 THROW 键 → EnterVehicle()
  ├── 将 driver 引用设为玩家 CActorNpcControl
  ├── 缓存玩家当前输入状态（m_NavMeshAgent.isStopped = true 停住玩家AI）
  ├── 将玩家 GameObject.SetActive(false) 或设为不可见
  └── 后续 Update 中，载具的移动由自身 Rigidbody2D 处理
       玩家的输入（PUNCH/KICK/JUMP）通过 CInputControl 查询后转发为载具武器触发

下车 → ExitVehicle()
  ├── 恢复玩家 CActorNpcControl
  ├── 玩家位置设为载具侧方偏移
  ├── 给予 0.5s 无敌帧（通过 CActorParameter 的临时 Buff）
  └── driver = null
```

**Harmony Patch 注入点：**

| Patch 目标 | Patch 类型 | 目的 |
|---|---|---|
| `CActorNpcControl.UpdateAiInformation` | Prefix | 驾驶员上车时跳过 AI 更新 |
| `CInputControl.IsKey(EnumKeyID)` | Postfix | 驾驶员上车时，THROW 键触发下车而非投掷 |
| `CActorManager.UpdateActorList` | Postfix | 载具作为独立对象注册到更新列表 |

### 3.4 火神机枪实现方案

火神机枪是无限连发子弹，复用原版子弹系统：

1. **子弹生成**：通过 `CBulletItemControl.Initialize` 创建子弹实例
2. **子弹数据**：使用现有 `mstBulletDataData` 中的低伤害子弹条目，或新增自定义 bullet ID
3. **射击逻辑**：在 `ModVehicle.FixedUpdateRun` 中计时，每 0.08s 调用一次 `FireVulcan()`
4. **子弹方向**：根据 `facing` 设置子弹初速度方向
5. **视觉**：复用 `EnumEffect.Fire` 或自定义枪口闪光

```csharp
// 伪代码：火神机枪射击
void FireVulcan()
{
    vulcanCooldown = VULCAN_INTERVAL;
    // 从对象池取子弹
    var bullet = BulletPool.Get();
    bullet.transform.position = turretFirePoint.position;
    bullet.Initialize(bulletData /* 低伤害高速子弹 */);
    bullet.SetDirection(facing * Vector2.right);
    // 播放枪口火焰特效
    EffectManager.Play(EnumEffect.Fire, turretFirePoint.position);
}
```

### 3.5 主炮实现方案

主炮是抛物线榴弹 + AOE 伤害：

1. **榴弹**：同火神机枪子弹生成方式，但使用抛物线运动（初始速度带 Y 分量）
2. **AOE 伤害**：榴弹命中后，在半径范围内对所有 `CObjectControl` / `CActorNpcControl` 调用 `CAttackCollision.HitFunc`
3. **弹药限制**：`cannonAmmo = 5`，每次射击减 1，归零后不能发射
4. **冷却**：0.8s 冷却计时

```csharp
void FireCannon()
{
    cannonCooldown = CANNON_INTERVAL;
    cannonAmmo--;
    // 生成抛物线榴弹
    var grenade = BulletPool.Get();
    grenade.transform.position = turretFirePoint.position;
    grenade.Initialize(grenadeData /* AOE 榴弹 */);
    grenade.SetVelocity(new Vector2(facing * 600f, -100f));
    // 榴弹命中回调
    grenade.OnHit += OnGrenadeExplode;
}

void OnGrenadeExplode(Vector2 position)
{
    // AOE 伤害：查找半径内所有角色
    var hitResults = Physics2D.OverlapCircleAll(position, BLAST_RADIUS);
    foreach (var hit in hitResults)
    {
        var actor = hit.GetComponent<CActorNpcControl>();
        if (actor != null && actor != driver)
        {
            // 通过 CAttackCollision 施加伤害
            var atkCol = attackCollisionPool.Get();
            atkCol.Init(position, attackData /* AOE 高伤害 */, teamID);
            atkCol.HitFunc(actor);
        }
    }
    // 播放爆炸特效
    EffectManager.Play(EnumEffect.Explosion_Fire, position);
}
```

### 3.6 耐久自爆逻辑

```csharp
void TakeDamage(int dmg)
{
    if (invincibleTimer > 0f || destroyed) return;
    durability--;
    hitFlashTimer = 0.15f;
    // 红闪
    spriteRenderer.color = Color.red;

    if (durability <= 0)
    {
        Explode();
    }
}

void Explode()
{
    destroyed = true;
    // 强制跳车
    if (driver != null) ExitVehicle();
    // AOE 伤害（同主炮爆炸）
    OnGrenadeExplode(transform.position);
    // 播放爆炸特效
    EffectManager.Play(EnumEffect.Explosion_Fire, transform.position);
    EffectManager.Play(EnumEffect.Smoke_Small, transform.position);
    // 延迟销毁
    Destroy(gameObject, 0.5f);
}
```

## 四、可破坏物系统注入方案

### 4.1 总体判断

**原版有 Gimmick 系统和 CObjectControl 基类，但没有"HP + 破坏 + 掉落"一体化的可破坏物组件。**

可破坏物系统应：
1. 复用 `CGimmickCollision` 的受击检测机制（已能响应攻击）
2. 扩展 `CObjectControl` 的物理/渲染能力
3. 新增 `ModDestructibleObject` 组件实现 HP/破坏/掉落逻辑
4. 通过新增 `CModDestructibleGenerator`（仿照 `CItemGenerator`）在关卡中放置

### 4.2 可破坏物基类设计

```
ModDestructibleObject (新增 MonoBehaviour)
├── 挂载位置：继承 CObjectControl 的场景物体 GameObject
├── 依赖系统：
│   ├── CGimmickCollision（受击检测，复用其 SetGimmickAttackData）
│   ├── CObjectControl（物理/渲染基类）
│   ├── CItemGenerator（掉落物生成对接）
│   └── EnumEffect（破坏特效播放）
├── 配置字段：
│   ├── maxHits: int（最大受击次数，默认 3，贩卖机 2）
│   ├── destructibleType: enum（Generic / VendingMachine）
│   ├── dropItemType: EnumItemType[]（掉落物类型表）
│   ├── breakEffect: EnumEffect（破坏时播放的特效）
│   └── damageEffect: EnumEffect（受击时播放的特效）
├── 状态：
│   ├── currentHits: int（已受击次数）
│   └── destroyed: bool
└── 核心方法：
    ├── TakeDamage(int dmg)
    ├── PlayHitEffect()
    ├── OnDestroyed()
    └── SpawnDrops()
```

### 4.3 受击检测对接方案

**复用原版 `CGimmickCollision`：**

原版 `CGimmickCollision` 已有 `m_AttackCollisionID` 和 `SetGimmickAttackData`，说明场景物体受击机制已经存在。可破坏物的对接方式：

```csharp
// 在 ModDestructibleObject.Awake() 中
void Awake()
{
    // 获取同 GameObject 上的 CGimmickCollision
    gimmickCollision = GetComponent<CGimmickCollision>();
    if (gimmickCollision != null)
    {
        // 设置可破坏物的攻击碰撞数据
        // （使用 mstAttackCollisionData 中对应的条目）
        gimmickCollision.SetGimmickAttackData(attackCollisionID);
    }
    // 注册受击回调
    // 通过 Harmony Patch CGimmickCollision.HitFunc 的 Postfix
    // 来调用 ModDestructibleObject.TakeDamage()
}
```

**Harmony Patch 注入点：**

| Patch 目标 | Patch 类型 | 目的 |
|---|---|---|
| `CGimmickCollision.HitFunc` | Postfix | 检测到被攻击时，调用挂载的 `ModDestructibleObject.TakeDamage` |
| `CAttackCollision.HitFunc` | Postfix | 补充子弹类攻击对可破坏物的判定 |

### 4.4 放置/生成方案

**方案 A：新增生成器（推荐）**

```csharp
            Debug.Log("[RiverCityMod] 载具+可破坏物 mod 已加载");

    /// <summary>
    /// Patch: CGimmickCollision.HitFunc Postfix
    /// 目的：场景物体被攻击时，通知挂载的 ModDestructibleObject
    /// </summary>
    [HarmonyPatch(typeof(CGimmickCollision), "HitFunc")]
    public static class GimmickCollisionHit_Patch
    {
        static void Postfix(CGimmickCollision __instance)
        {
            var destructible = __instance.GetComponent<ModDestructibleObject>();
            if (destructible != null && !destructible.destroyed)
            {
                // 从攻击碰撞数据获取伤害值
                int damage = __instance.get_attack_Data != null 
                    ? __instance.get_attack_Data.damage 
                    : 1;
                destructible.TakeDamage(damage);
            }
        }
    }

    /// <summary>
    /// Patch: CActorNpcControl.UpdateAiInformation Prefix
    /// 目的：驾驶员上车时跳过 AI 更新
```

| 物理复用 | 中 | `CObjectControl` 的 Rigidbody2D/碰撞可复用，但需自行处理驾驶移动 |

| 特效复用 | 高 | `EnumEffect.Explosion_Fire` + `Fire` 可直接用于枪口闪光和爆炸 |
| AI 交互 | 中 | 需 Harmony Patch 让驾驶员上车时跳过 `CActorNpcControl.UpdateAiInformation` |
| 动画 | 低 | 原版 839 个动作状态中无驾驶动作，载具自身动画（轮子旋转/炮塔转动）需自建 |
| **总体** | **中** | 代码逻辑可写，但需新建完整组件 + 预制体 + 美术资源。主要工作量在物理移动和与 CActor 的解耦 |

### 7.2 可破坏物系统 — **可行性：高**

| 维度 | 评估 | 说明 |
|---|---|---|
| 原版基础 | 有 | `CGimmickCollision` 已有受击检测，`CObjectControl` 是物理基类 |
| 受击对接 | 高 | Harmony Patch `CGimmickCollision.HitFunc` Postfix 即可接入 |
| 特效复用 | 高 | 原版已有 7 种材质破坏特效 + 5 种爆炸特效 |
| 掉落物对接 | 高 | `CItemGenerator` + `EnumItemType` 193 种道具可直接复用 |
| 放置方案 | 高 | 仿照 `CItemGenerator` 新建生成器，或直接场景放置 |
| **总体** | **高** | 原版已有完整的场景物体受击框架，只需新增 HP/破坏/掉落逻辑层 |

### 7.3 综合评估

| 系统 | 可行性 | 预计工作量 | 风险点 |
|---|---|---|---|
| 载具系统 | **中** | 5~8 天 | 与 CActor 的解耦（AI 状态机不支持乘客概念）、物理移动手感调试 |
| 可破坏物系统 | **高** | 2~3 天 | 低风险，主要是配置掉落表和预制体 |
| **合计** | **中-高** | **7~11 天** | 载具是主要工作量，可破坏物相对简单 |

### 7.4 关键风险提示

1. **CActor 状态机不支持"乘客"模式**：原版角色的移动/碰撞完全由 `CActorNpcControl` + NavMesh 驱动，载具需要在外部接管输入并隐藏角色，这种"外部覆盖"方式在边缘情况（如角色被推开/眩晕）可能出 bug。
2. **动画资源缺失**：原版没有载具相关的动画，轮子旋转/炮塔转动只能用程序动画（Tween/协程），视觉表现力有限。
3. **可破坏物受击帧**：`CGimmickCollision` 的受击检测帧（`validFrame`）需要从 `mstAttackCollisionData` 配置中找到合适的条目，如果找不到匹配的，可能需要自定义攻击碰撞数据。
4. **主炮 AOE 伤害范围**：原版 `CAttackCollision` 是基于单个目标的命中判定，AOE 需要手动遍历范围并逐个调用 `HitFunc`，需注意性能（每帧 OverlapCircleAll）。

## 1. Godot Buff + 敌人 AI 设计摘要（从 .gd 提取）

### 1.1 Buff 系统（`buff.gd`，30 行常量定义）

| Buff 键 | 来源物品 | 效果 | 持续时间 |
|---|---|---|---|
| `sports_drink` | 运动饮料 | **移动速度 +30%** | 15.0 s |
| `chili_rice` | 辣炒饭 | **攻击伤害 +50%** | 15.0 s |
| `iron_pipe` | 铁管（增益化） | **近战范围 +50%** | 20.0 s |
| `armor_vest` | 防弹背心 | **受到伤害 −50%** | 20.0 s |

- 掉落：丧尸死亡 **10%** 概率掉落，随机池 `["chili_rice","iron_pipe","armor_vest"]`（不含 sports_drink，后者靠拾取）。
- 叠加/倒计时/倍率结算在 `player.gd` 的 `active_buffs` 字典中实现；本文件只维护常量与文案，便于扩展。

### 1.2 普通敌人 5 种 AI 行为（`zombie.gd`，962 行）

敌人类型枚举 `Type { WALKER, RUNNER, FAT, DELINQUENT, BOSOZOKU }`，行为由状态/计时器驱动：

| 行为 | 触发 | 实现要点 |
|---|---|---|
| **发呆（zone_out / look_at_watch / fix_hair）** | 5%/秒 随机；人形敌倍率 1.5× | `silly_state` 非追踪状态，受击 20% 概率惊醒 |
| **互殴（brawl / argue）** | 3%/秒（人形 8%/秒），40~60px 内找同类 | 互殴期间每秒回 1 血；结束后 30% 人形敌"记仇" |
| **偷吃（snack）** | 2%/秒 | 纯演出 silly_state |
| **逃跑（flee）** | 仅 `can_flee` 类型，HP ≤ 30%（`flee_hp_ratio`） | 每帧 5% 概率进入，远离玩家、速度 ×1.3、持续 ~2s |
| **躲避（dodge）** | 远程子弹命中；连续被命中 ≥ `hit_streak_threshold(3)` | 0.3s 侧移 ×1.8 速，冷却 1.5s，概率 40% |
| **包抄（surround）** | 同屏 ≥3 只且靠近玩家 | 30% 个体叠加上下正弦偏移 `±SURROUND_Y(20px)` |
| **爆发冲锋** | runner 冲锋前摇 0.4s（红眼 telegraph）→ ×2.5 速冲刺 | `dash_state = telegraph/dash` |

**打残收服（核心特色）**：
- 求饶血量阈值 `CAPTURE_THRESHOLD = 2`（不良少年 3、暴走族 4）；**最后一击必须是近战**且 `0 < HP ≤ 阈值` → 进入 `begging`（下跪、举手、气泡"饶命！"），并从 `zombies` 组移除（不再被 AOE 命中）。
- 逃跑中被近战命中还有 40% 概率直接求饶。
- 玩家对求饶者调用 `capture()` → 返回援护数据（伤害值/性格标签/人形标记），敌人变为同伴。

精英吸血 8%（普通小怪 5%）。

### 1.4 Boss 三阶段（`boss.gd`，811 行；定义在 `enemy_defs.gd`）

两个 Boss：`street_boss`（暴走族总长·鬼冢，HP 400）、`final_boss`（学生会会长·白岳，HP 800）。

- **阶段判定**：每帧 `_check_phase()`，按 `HP / maxHP` 阈值：`< 0.66` → 阶段 2，`< 0.33` → 阶段 3。
- **阶段 1（近战压制）**：`punch_combo` + `body_slam`，speed/damage 倍率 1.0。
- **阶段 2（召唤冲刺）**：加 `dash_charge`，speed ×1.2~1.3，damage ×1.2~1.3，每 11~12s 召唤 3~4 小怪。
- **阶段 3（狂暴吸血）**：再加 `lifesteal_frenzy`，speed ×1.5~1.6，damage ×1.4~1.5，召唤间隔缩到 9~10s、数量 4~5，吸血率 ×2（→20%）。
- **阶段转换演出**：身体 1.2→1.0 回弹 + 抖动 + 眼睛变色（阶段2 橙、阶段3 红）+ 0.5s 过渡后摆姿势 1.5s，期间 **弱点激活（伤害 ×2）**。
- 吸血：Boss 基础 10%，按造成伤害回血不超过最大血。

### 1.5 波次配置（`level_config.gd`，99 行）

5 关，每关 `wave_config[]`，每波 `{walkers, runners, fat, interval}`：

| 关 | 名称 | 波数 | 趋势 |
|---|---|---|---|
| 1 | 黄昏町街道 | 5 | 3~5 walkers，0~1 runner，interval 1.5→0.9 |
| 2 | 白鹰高中 | 5 | 4~6 walkers，1~3 runner，0~2 fat |
| 3 | 暴走族聚集地 | 6 | 5~8 walkers，2~5 runner，1~3 fat |
| 4 | 白岳制药工厂 | 6 | 5~8 walkers，2~5 runner，1~4 fat |
| 5 | 终章·最终 Boss 战 | 3 | 前 2 波混合，**第 3 波 `boss_id = "final_boss"`** |

`interval` 即同波敌人之间的生成间隔（秒）。`level.gd`（67 行）仅做背景色/BGM 氛围演出，不参与刷怪逻辑。

- 字段：`<m_AITribe>k__BackingField`

## 3. Buff 系统注入方案

### 3.1 设计：把 Godot 4 buff 映射到原版 CStatusEffect

原版已有 `CStatusEffectManager.m_Effects` 列表 + `AddEffect/RemoveEffect/RecalcBuffEffect` + 静态 `CDamageCalculator.Buff_Mul/Buff_Add`，**不需要新写 buff 框架**，只需：
1. 在 `mstStatusEffectDataData` 表里登记 4 个新 buff 行（ID 自定，避开已占用）；
2. 用 Harmony 给 `CStatusEffectManager.RecalcBuffEffect` 打 Postfix，按 `EffectType` 把 4 种 buff 折算到 `CActorParameter.SetBuffValue`；
3. 用 Harmony 给 `CDamageCalculator.Buff_Mul` / `Buff_Add` 打 Postfix 叠加"攻击+50% / 受伤−50%"。

| Godot buff | 映射 EffectType | 数值落点 | 时长 |
|---|---|---|---|
| `sports_drink` 速度+30% | SPEED_UP | `CActorParameter.m_Speed` ×1.3 | 15s |
| `chili_rice` 攻击+50% | ATTACK_UP | `CDamageCalculator.Buff_Mul` ×1.5 | 15s |
| `iron_pipe` 近战范围+50% | RANGE_UP | 攻击判定距离 ×1.5（改 `m_NowRange`） | 20s |
| `armor_vest` 受伤−50% | DEFENSE_UP | `Buff_Mul`（受伤侧）×0.5 | 20s |

叠加规则：同名 buff 刷新时间不叠加；不同 buff 乘区独立；`IsEternal=false`，靠 `EffectTime` + `CountGameTime` 倒计时，到点 `Disable()`。

### 3.2 C# Harmony 参考代码

```csharp
using HarmonyLib;
using NK21;
using UnityEngine;

// ============================================================
//  自定义 buff ID（与 mstStatusEffectDataData 新增行对应）
//  取一个不与原版冲突的高位段，例如 9000+
// ============================================================
public static class ZombieBuffIDs
{
    public const int SPEED_UP     = 9001; // sports_drink  速度 +30%
    public const int ATTACK_UP    = 9002; // chili_rice    攻击 +50%
    public const int RANGE_UP     = 9003; // iron_pipe     近战范围 +50%
    public const int DEFENSE_UP   = 9004; // armor_vest    受伤 -50%
}

// ============================================================
//  3.2.1 拾取/击杀掉落 → 给目标 actor 上 buff
//  调用方：击杀敌人后 10% 概率、或拾取道具时
// ============================================================
public static class ZombieBuffApplier
{
    // 给指定 actor 施加一个限时 buff（走原版 AddEffect 通道）
    public static void ApplyBuff(CActorParameter targetParam, int effectId, float durationSec)
    {
        if (targetParam == null) return;

        // 原版 CStatusEffect 实例：用公开 setter 填字段
        var eff = new CStatusEffect();
        eff.set_ID(effectId);
        eff.set_EffectTime(durationSec * 60f);   // 原版按帧计时（60fps），秒→帧
        eff.set_IsEternal(false);
        eff.set_IsNotRemoved(false);
        eff.set_FrameCount(0);

        switch (effectId)
        {
            case ZombieBuffIDs.SPEED_UP:
                eff.set_EffectValue1(1.30f);     // 速度倍率
                eff.set_EffectType(21);          // 自定义类型标记（对齐 etype 表新增行）
                break;
            case ZombieBuffIDs.ATTACK_UP:
                eff.set_EffectValue1(1.50f);     // 攻击倍率
                eff.set_EffectType(22);
                break;
            case ZombieBuffIDs.RANGE_UP:
                eff.set_EffectValue1(1.50f);
                eff.set_EffectType(23);
                break;
            case ZombieBuffIDs.DEFENSE_UP:
                eff.set_EffectValue1(0.50f);     // 受伤倍率（乘到受伤侧）
                eff.set_EffectType(24);
                break;
        }

        // CStatusEffectManager 挂在 actor 上；通过 targetParam 所在 actor 取到。
        // 具体取引用方式依原版 actor 聚合结构而定（见 3.3 备注）。
        CStatusEffectManager mgr = StatusEffectResolver.Resolve(targetParam);
        if (mgr != null)
            mgr.AddEffect(eff);                  // 原版堆叠/去重/倒计时由它负责
    }
}

// ============================================================
//  3.2.2 Postfix：RecalcBuffEffect 重算时，把 4 种 buff 写进参数
//  原版每帧/效果变化时调用 RecalcBuffEffect
// ============================================================
[HarmonyPatch(typeof(CStatusEffectManager), "RecalcBuffEffect")]
public static class Patch_RecalcBuffEffect
{
    static void Postfix(CStatusEffectManager __instance)
    {
        CActorParameter p = __instance.m_TargetActor;   // 字段经 dnfile 确认存在
        if (p == null) return;

        float speedMul = 1f, rangeMul = 1f;
        // 遍历 m_Effects，按 ID 叠加（同名取最新）
        foreach (CStatusEffect e in __instance.m_Effects)
        {
            if (e == null || !e.get_IsActive()) continue;
            switch (e.get_ID())
            {
                case ZombieBuffIDs.SPEED_UP:  speedMul *= e.get_EffectValue1(); break;
                case ZombieBuffIDs.RANGE_UP:  rangeMul *= e.get_EffectValue1(); break;
            }
        }
        // 速度倍率写回运行时参数（m_Speed 字段、get/set 经 dnfile 确认）
        p.m_Speed = Mathf.Max(1f, p.m_Speed * speedMul);
        // 攻击/防御倍率交给 CDamageCalculator 的 Buff_Mul（见下），这里用 SetBuffValue 存住
        p.SetBuffValue(ZombieBuffIDs.ATTACK_UP,  AttackMulOf(__instance));
        p.SetBuffValue(ZombieBuffIDs.DEFENSE_UP, DefenseMulOf(__instance));
    }

    static float AttackMulOf(CStatusEffectManager m)
    {
        float mul = 1f;
        foreach (CStatusEffect e in m.m_Effects)
            if (e != null && e.get_IsActive() && e.get_ID() == ZombieBuffIDs.ATTACK_UP)
                mul *= e.get_EffectValue1();
        return mul;
    }
    static float DefenseMulOf(CStatusEffectManager m)
    {
        float mul = 1f;
        foreach (CStatusEffect e in m.m_Effects)
            if (e != null && e.get_IsActive() && e.get_ID() == ZombieBuffIDs.DEFENSE_UP)
                mul *= e.get_EffectValue1();
        return mul;
    }
}

// ============================================================
//  3.2.3 Postfix：静态 Buff_Mul —— 攻击方 ATTACK_UP 乘算
//  签名经 dnfile 确认：public static Buff_Mul(...)
// ============================================================
[HarmonyPatch(typeof(CDamageCalculator), "Buff_Mul")]
public static class Patch_Buff_Mul
{
    // 原版返回一个累计倍率；Postfix 在返回值上乘上我方攻击 buff
    static void Postfix(CActorParameter attacker, ref float __result)
    {
        if (attacker == null) return;
        float atkBuff = attacker.GetBuffValue(ZombieBuffIDs.ATTACK_UP); // 默认 1
        if (atkBuff > 1f) __result *= atkBuff;
    }
}

// 防御 buff 一般作用在"受伤侧"。若原版 Buff_Mul 同时用于攻防两侧，
// 则再打 CalcDealtDamage 的 Postfix，对受害方乘 DefenseMul：
[HarmonyPatch(typeof(CDamageCalculator), "CalcDealtDamage")]
public static class Patch_CalcDealtDamage_Defense
{
    static void Postfix(CActorParameter ___target, ref int __result)
    {
        // 字段名 ___target 需按 IL 形参名微调（见 3.3 备注）
        if (___target == null) return;
        float def = ___target.GetBuffValue(ZombieBuffIDs.DEFENSE_UP);
        if (def < 1f) __result = Mathf.Max(1, (int)(__result * def));
    }
}
```

### 3.3 备注（注入时需现场确认）

- `CStatusEffectManager.m_TargetActor`、`CActorParameter.SetBuffValue/GetBuffValue`、`m_Speed` 字段均经 dnfile 确认存在；但 `Buff_Mul` / `CalcDealtDamage` 的**形参名**无法只读元数据确定（需 IL）。Harmony 里用 `___参数类型` 反射注入或 `[HarmonyArgument(0)]` 按位置取参即可。
- 取 `CStatusEffectManager` 实例：原版它是 actor 聚合成员，建议在第一次 patch 命中时用 `Traverse` 或公共 getter 缓存 `m_TargetActor → 其持有的 manager`，避免每帧查找。
- UI 图标：复用原版 `CStatusEffectIcon / CStatusEffectIconManager`（dnfile 确认存在），把新 buff 挂到 `m_IconManager` 即可显示，无需自写 HUD。

## 4. 敌人 AI 增强注入方案

### 4.1 框架：在 CAiStateMachine 下新增 Godot 风格状态

原版 `CAiStateBase` 是抽象类，三个 virtual 钩子 `Enter/Exec/Exit`。新增状态 = 继承它，挂到 `CActorNpcControl.StateMachine`（即 `CAiStateMachine`）。

```csharp
// 所有新增状态的基类：持有 NPC 控制器，方便取输入/导航/目标
public abstract class ZombieAiStateBase : CAiStateBase
{
    protected CActorNpcControl npc;        // dnfile 确认：StateMachine.Owner 类型
    protected CAiInputHelper input;        // npc.m_AiInputHelper（dnfile 字段）
    protected CAiNavMeshControl navi;      // npc.m_NavMeshControl

    public void Bind(CActorNpcControl ctrl)
    {
        npc   = ctrl;
        input = ctrl.m_AiInputHelper;
        navi  = ctrl.m_NavMeshControl;
    }
}

// ---- 状态① 发呆（zone_out）：原地不动，随机结束 ----
public class AiSillyIdle : ZombieAiStateBase
{
    float timer;
    public override void Enter()
    {
        timer = UnityEngine.Random.Range(1.0f, 2.5f);
        input.ClearDirection();
    }
    public override void Exec()
    {
        timer -= Time.deltaTime;
        input.m_VelocityX = 0f;            // 站桩
        // 取最大血量用 glue 解析器（CActorParameter.get_HpRateFloat / IsDead 经 dnfile 确认）
        float ratio = ParamResolver.HpRatioOf(npc);
        if (timer <= 0f || ratio <= 0.3f)
            npc.SetNextAIAction();          // 超时或被打残 → 回追击
    }
    public override void Exit() { }
}

// ---- 状态② 逃跑（flee）：远离目标，血线恢复或计时结束 ----
public class AiFlee : ZombieAiStateBase
{
    float timer = 2.0f;
    public override void Enter() { timer = 2.0f; }
    public override void Exec()
    {
        timer -= Time.deltaTime;
        // 目标方向取反 → 远离玩家；速度由外部 speedMult 处理
        Vector3 dir = npc.TargetDirectionVector;   // dnfile：get_TargetDirectionVector
        input.m_VelocityX = -dir.x * 1.3f;
        input.m_DiretionX = -dir.x;
        if (timer <= 0f) npc.SetNextAIAction();
    }
    public override void Exit() { }
}

// ---- 状态③ 躲避（dodge）：0.3s 侧移 ----
public class AiDodge : ZombieAiStateBase
{
    float t = 0.3f; float side;
    public override void Enter()
    {
        t = 0.3f;
        side = (UnityEngine.Random.value < 0.5f) ? -1f : 1f;
    }
    public override void Exec()
    {
        t -= Time.deltaTime;
        input.m_VelocityX = side * 1.8f;     // 侧移
        if (t <= 0f) npc.SetNextAIAction();
    }
    public override void Exit() { input.ClearVelocity(); }
}

// ---- 状态④ 包抄（surround）：横向偏移追击 ----
public class AiFlank : ZombieAiStateBase
{
    float sine;
    public override void Exec()
    {
        sine += Time.deltaTime * 3f;
        Vector3 dir = npc.TargetDirectionVector;
        input.m_VelocityX = dir.x + Mathf.Sin(sine) * 0.3f;
        input.m_DiretionX = dir.x;
    }
    public override void Enter() { }
    public override void Exit() { }
}

// ---- 状态⑤ 互殴（brawl）：转向另一只敌对 NPC 攻击 ----
public class AiBrawl : ZombieAiStateBase
{
    public override void Exec()
    {
        CActorNpcCell other = ZombieAiRegistry.FindNearestFriend(npc, range: 1.5f);
        if (other == null) { npc.SetNextAIAction(); return; }
        npc.SetAI_PlayerTarget(other.Transform);   // 复用目标设置
        input.m_Punch = true;                       // 出拳
    }
    public override void Enter() { }
    public override void Exit() { input.m_Punch = false; }
}
```

### 4.2 打残收服：利用 `AI_TRIBE.COMPANION` 切换阵营

这是整个方案的关键原生机制。残血时把敌人阵营从 `OPPOSITION` 改为 `COMPANION`：

```csharp
// ============================================================
//  Postfix：敌人受击后检查是否满足"打残收服"
//  挂在 CActorNpcControl.ActorDead 之前的伤害结算路径，
//  或直接 patch CActorParameter.SetDamage 的 Postfix。
// ============================================================
[HarmonyPatch(typeof(CActorParameter), "SetDamage")]
public static class Patch_CaptureOnLowHP
{
    static void Postfix(CActorParameter __instance)
    {
        // 非敌人 / 已死 / 已是同伴 → 跳过
        CActorNpcControl npc = NpcLocator.Of(__instance);
        if (npc == null) return;
        if (npc.get_m_AITribe() == AI_TRIBE.COMPANION) return;
        if (__instance.IsDead()) return;

        float ratio = __instance.get_HpRateFloat();   // dnfile 确认
        const float CAPTURE_RATIO = 0.30f;            // Godot: flee_hp_ratio=0.3
        if (ratio > CAPTURE_RATIO) return;

        // 仅"最后一击为近战"才求饶（Godot: is_melee && 0<hp<=阈值）
        // 这里由伤害来源标记 melee（外层传入），简化为：残血即触发
        if (ZombieBattleFlags.LastHitWasMelee(__instance))
        {
            // 1) 阵营切换：OPPOSITION → COMPANION（原生方法）
            npc.set_m_AITribe(AI_TRIBE.COMPANION);

            // 2) 目标改为敌方（原版会自动让它去打 OPPOSITION）
            npc.SetAI_TargetPos(Vector3.zero);

            // 3) 触发收服演出：暂停、下跪、气泡（复用 BossGaugeBase/演出或自写）
            ZombieRecruitPopup.Show(npc);

            // 4) 通知刷怪系统：本敌转为同伴，不计入"待击杀"
            CActorNpcManager.CallOnCompanionSpawn?.Invoke(npc);
        }
    }
}
```

> **为什么可行**：`opponentList`（dnfile 字段）是原版维护的敌对列表，切换 `m_AITribe` 后 AI 的目标筛选会自然把它从"要打的敌人"挪到"队友"。这就是调查报告指出的"不需要全新增系统"。

## 5. Boss 三阶段注入方案

### 5.1 利用 `m_SetHpCallback_BOSS` 做阶段转换

`CActorParameter.m_SetHpCallback_BOSS` 是 HP 变化委托。Boss 注册它，每帧 HP 变化时读 `get_HpRateFloat()` 判断阈值：

```csharp
public class BossPhaseController
{
    CActorParameter param;
    CActorNpcControl npc;
    int phase = 1;

    public void Bind(CActorNpcControl bossNpc)
    {
        npc = bossNpc;
        param = ParamResolver.Of(npc);          // glue：npc.m_MyOwner → CActorParameter（m_SetHpCallback_BOSS 经 dnfile 确认）
        // 把我们的回调挂到原版 Boss HP 回调链（字段经 dnfile 确认存在）
        param.m_SetHpCallback_BOSS = (System.Action<float>)OnHpChanged;
    }

    void OnHpChanged(float _hp)
    {
        float r = param.get_HpRateFloat();      // dnfile 确认
        int newPhase = 1;
        if      (r < 0.33f) newPhase = 3;
        else if (r < 0.66f) newPhase = 2;

        if (newPhase == phase) return;
        phase = newPhase;
        OnPhaseChange(newPhase);
    }

    void OnPhaseChange(int p)
    {
        var def = ZombieBossTable.Get(npc);     // {speedMult, dmgMult, attacks, summon, lifestealMult}
        // 1) 改速度
        param.m_Speed = def.baseSpeed * def.speedMult;
        // 2) 改攻击模式：切 AI 状态 / 限定 EnumActPattern 白名单
        ZombieActPatternLimiter.SetAllowed(npc, def.attacks);   // 如 {PUNCH_Ground, KICK_Ground, Dash, Throw}
        // 3) 阶段3 吸血强化
        if (p == 3) param.SetBuffValue(/*lifesteal*/12, def.lifestealMult);
        // 4) 演出：摆姿势 + 弱点窗口 + 血条变色
        BossGaugeFx.PlayPhaseTransition(npc, p);
        // 5) 召唤小怪
        if (def.summonMinions)
            ZombieWaveRunner.ScheduleSummon(npc, def.summonCount, def.summonInterval);
    }
}
```

### 5.2 每阶段攻击模式切换

原版 `EnumActPattern`（44 项）已覆盖全部需要的攻击：阶段 1 放 `PUNCH_Ground / KICK_Ground / Throw`；阶段 2 加 `Dash / Dash_Punch`；阶段 3 再加 `SP_Ground_Only`（狂暴技能）。用一个 patch 限制 AI 候选：

```csharp

    {

        if (allowed != null && !allowed.Contains(__result))
            __result = ZombieActPatternLimiter.Fallback(__instance);  // 退到白名单内
    }
}
```

### 5.3 Boss 血条 / 特写对接

- 血条：`CEnemyGaugeManager.Attach(npc)` 把 Boss 挂到 Boss 血条；`BossGaugeBase.get_Ber_Per()` 读 HP 比率；阶段切换时调 `BossGaugeFx` 改颜色。

## 6. 波次刷怪系统注入方案

### 6.1 原版生成机制分析

原版是**开放世界刷点**模型，不是清版波次：
- `mstEnemyPopData`：每个刷点有 `activeamount`（同屏上限）、`delay`（首次延迟）、`refilldelay`（补怪间隔）、`group_1..7 + prob_1..7`（按概率抽群）、`stageid/dayvalue/timezone`（昼夜/进度门控）。
- `mstEnemyGroupData`：一个群 = `charaid_1..8`（最多 8 个角色）+ `droptable`。
- `CNpcGenerator`：持有 `m_EnemyData`、`m_ActiveEnemyNum`、`m_EnemyCoroutine`，协程式补怪；`IsExtinct()` 判断是否清完。
- `CActorNpcManager`：`ActivateGenerator()` 激活刷点；`AddEnemySpawnDelegate/CallOnEnemySpawn` 提供生成回调钩子。

### 6.2 实现 Godot 式波次配置

不改原版生成器，而是**在其上做一个波次调度器**：用 `mstEnemyPopData` 的 `group/prob` 表达"每波敌种"，用协程按 `interval` 连续调 `GenerateEnemy`：

```csharp
// 波次定义（对应 Godot level_config.gd 的 wave_config）
public class ZombieWaveDef
{
    public int walkers, runners, fat;     // 各敌种数量
    public float interval;                 // 同波生成间隔
    public string bossId;                 // 末波 Boss（可选）
}

public class ZombieWaveRunner : MonoBehaviour
{
    ZombieWaveDef[] waves;
    int waveIndex;
    CEventNpcGenerator gen;               // dnfile：GenerateEnemy 入口

    public void StartWave(int levelIdx)
    {
        waves = ZombieLevelTable.Get(levelIdx).waves;   // 5 关波次表
        waveIndex = 0;
        StartCoroutine(RunWave());
    }

    System.Collections.IEnumerator RunWave()
    {
        while (waveIndex < waves.Length)
        {
            var w = waves[waveIndex];
            // 按 interval 逐个刷：walker→runner→fat
            for (int i = 0; i < w.walkers; i++) { gen.GenerateEnemy(CharaId.Walker); yield return new WaitForSeconds(w.interval); }
            for (int i = 0; i < w.runners; i++) { gen.GenerateEnemy(CharaId.Runner); yield return new WaitForSeconds(w.interval); }
            for (int i = 0; i < w.fat; i++)     { gen.GenerateEnemy(CharaId.Fat);     yield return new WaitForSeconds(w.interval); }

            if (w.bossId != null) SpawnBoss(w.bossId);

            // 等本波敌人清完（或被收服）再进下一波
            yield return new WaitUntil(() => gen.IsExtinct() || AllRecruitedOrDead());
            waveIndex++;
        }
        StageClear();
    }

    void SpawnBoss(string id)
    {
        var boss = gen.GenerateEnemy(ZombieBossTable.CharaIdOf(id));
        new BossPhaseController().Bind(boss);                 // 接第 5 节
        CEnemyGaugeManager.Instance.Attach(boss);             // 接 Boss 血条
    }
}
```

> 实现要点：`CEventNpcGenerator.GenerateEnemy`、`CNpcGenerator.IsExtinct`、`CActorNpcManager.CallOnEnemySpawn` 均经 dnfile 确认。波次"间隔"= `WaitForSeconds(w.interval)`；"每波种类/数量"= 查 `ZombieLevelTable`（镜像 Godot `level_config.gd` 的 5 关数据）。

## 8. 可行性评估

| 子系统 | 可行性 | 理由（基于 dnfile 证据） |
|---|---|---|
| **Buff 系统** | **高** | 原版已有完整 `CStatusEffectManager`（AddEffect/RemoveEffect/RecalcBuffEffect）+ 静态 `Buff_Mul/Buff_Add` + `CActorParameter.SetBuffValue/GetBuffValue`。4 种 buff 只是加数据表行 + 两个 Postfix。无需新框架。 |
| **打残收服（阵营切换）** | **高** | `AI_TRIBE={OPPOSITION,COMPANION}` + `CActorNpcControl.set_m_AITribe` 是原生方法。残血改阵营即可，目标筛选靠原版 `opponentList` 自动完成。这是本方案风险最低的亮点。 |
| **新增普通敌 AI 状态** | **高** | `CAiStateBase` 抽象 virtual Enter/Exec/Exit + `CAiStateMachine.ChangeState/SetCurrentState` 是标准 FSM。继承基类即可，导航/输入用现成 `CAiNavMeshControl.SetPath`、`CAiInputHelper`。 |
| **精英敌人** | **中-高** | 数据驱动（`mstEnemyGroupData` 指 charaid + `mstActorParamaterData` 调属性）容易；"躲子弹/突进/范围挥击"需自写 3 个 AI 状态并 patch `Init` 注册，工作量集中在行为调参。 |
| **Boss 三阶段** | **高** | `m_SetHpCallback_BOSS` 委托 + `get_HpRateFloat()` 是完美钩子；攻击模式用 `EnumActPattern` 白名单 patch `CAiShortMove.NextAI`；血条 `CEnemyGaugeManager.Attach`、特写 `mstBossCutInDefineData` 现成。 |
| **波次刷怪** | **中** | 原版是开放世界补怪模型（`mstEnemyPopData`+`CNpcGenerator`），没有现成"波次"概念。好在 `CEventNpcGenerator.GenerateEnemy` + `IsExtinct` + `CallOnEnemySpawn` 够用，外层包一个协程波次调度器即可。难点是让"波次清完才进下一波"与原版自动补怪不冲突（需临时把 `activeamount` 设为波次目标、关 refill）。 |
| **数据表新增行** | **中** | DLL 不含数值，需在 Addressables 的 .asset 资源侧加行。若不打算动资源，也可在运行时 patch `mstEnemyGroupData.dataArray` 直接 push 新对象——但依赖资源加载时机，需在 `OnEnable`/首次访问前注入。 |

### 总体结论

**本融合方案技术上成立，且最大限度复用了原版原生机制：**
- Buff → 复用 `CStatusEffectManager` + `Buff_Mul/Buff_Add`；
- 收服 → 复用 `AI_TRIBE` 阵营切换（**最关键的原生彩蛋**）；
- AI → 继承 `CAiStateBase` 挂入 `CAiStateMachine`；
- Boss 三阶段 → 挂 `m_SetHpCallback_BOSS`；
- 波次 → 在 `CEventNpcGenerator` 外包协程调度。

**主要不确定性**（受只读元数据限制，需在有 dnSpy/ILSpy 的环境二次确认）：
1. `Buff_Mul` / `CalcDealtDamage` 的确切形参签名（Harmony 用位置取参兜底）；
2. `CStatusEffectManager` 如何从 actor 聚合中获取（建议首次命中时缓存）；
3. 数值表行的实际数值在 .asset 资源，本方案只给结构不给字面值。

## 三、商店扩展注入方案

### 3.1 设计思路

原版已有 **7 种业态**（STORE/EQUIP/COOK/RECYCLE/SENTOU/CAFE/MACHINE）和完整的商品/购买记录系统。Godot 的 4 分类（弹药/装备/食物/技能书）不需要新增业态，而是**映射到现有业态框架内**：

| Godot 分类 | 映射到原版业态 | 说明 |
|---|---|---|
| ammo（弹药） | STORE（一般商店） | 消耗品，`mstConsumableDataData.eenumsumableitem` 对应弹药类 |
| gear（装备） | EQUIP（装备店） | 装备品，`mstEquipDataData` 对应 |
| food（食物） | COOK（料理店） | 回复类消耗品，`mstConsumableDataData.effectid` = 回血 |
| skill（技能书） | STORE（一般商店）+ 特殊效果 | 消耗品，`effectid` = 学技能，使用后触发 `LearnSpWaza` |

**核心策略**：不新增 SHOP_TYPE，而是在现有 STORE/COOK/EQUIP 业态下，通过 `mstConsumableDataData` 和 `mstShopAssortData` 新增商品行来实现 Godot 风格的商品。

### 3.2 必杀书商品实现（核心特色）

**链路**：
```
mstConsumableDataData 新增行（必杀书）
  → effectid = 学技能效果ID
  → value1 = EnumWazaID 值（要习得的必杀技）
  → 玩家在商店购买 → 获得该消耗品
  → 玩家在背包使用 → CItemUseControl.UseItem()
    → 检测 effectid == 学技能 → 调用 CStorySaveData.LearnSpWaza(value1)
    → CSpecialMoveInfo.AddLearnedWazaListt(wazaId)

```

```csharp
                TryUnlockAchievement("hundred_kills", "百人斩");

        /// <summary>

        /// <summary>

        static void Unlock_Postfix(int achieveId)
        {
            // 映射原版成就到 Godot 风格解锁
            if (achieveId == (int)NKSP.Achievements.CLEAR_STORY_1)
            {

            }
```

### 7.4 总体评级

| 系统 | 可行性 | 工作量估计 |
|---|---|---|

| **合计** | **高** | **7-11天** |

### 7.5 关键风险与缓解

1. **effectid 数值不确定**：mstConsumableDataData.effectid 的"学技能"效果ID是编译在 ScriptableObject 资源中的，DLL 元数据不包含具体数值。**缓解**：通过 strings 扫描 DLL 中 "effectid" 附近的数字常量，或从游戏数据目录提取 .asset 文件确认。

2. **EnumConsumableItem 84项排查**：需确认原版是否已有"技能书"类消耗品，避免 ID 冲突。**缓解**：遍历 84 个枚举值对应的 mstConsumableDataData 行，检查 effectid 分布。

3. **AchievementsCollector 异步队列**：Unlock/Progress 方法内部有 QueueUnlock/QueueProgress 协程，直接调用可能需要主线程上下文。**缓解**：使用 AccessTools 调用公开方法，或在主线程 Update 中触发。

4. **Steam 成就 ID 映射**：新增成就需要在 Steamworks 后台配置对应的 Steam Achievement ID，否则 Unlock 后不会同步到 Steam。**缓解**：mod 阶段可仅做本地成就，Steam 对接后续按需添加。
