## 1. 概述

### 1.1 移植范围

|---|------|-----------|------------|--------|
| 1 | 拳3段/踢2段对齐 | Punch_1/2/3=162/163/164, Kick_1/2=175/176 | 已有框架，数值待对齐 | P0 |

| 3 | 冲刺攻击 | Dash=14 + Dash_Punch=173 + Dash_Kick=184 | 无 dash 攻击 | P1 |
| 4 | 交替加成 | CActorComboControl 双计数器 | 不存在 | P1 |
| 5 | 根性起身 | GutsHpRate + Reversal() + GetUp=130 | 不存在 | P1 |
| 6 | 合体技 | Two_Platoons_* + Kagemura_Combi_* | 不存在 | P2 |

| 9 | 伤害公式对齐 | CalcDealtDamage→Critical→Magnificate→Final | 直接 attack-damage | P0 |

## 3. 蓄力攻击

### 3.1 Unity 对应

| EnumAction | 值 | 说明 |
|------------|-----|------|
| Tame_Punch | 247 | 蓄力起手 |
| Tame_Punch_Charge | 248 | 蓄力中 |
| Tame_Punch_Attack | 249 | 蓄力释放 |
| Tame_Punch_End | 250 | 蓄力结束 |
| Tame_Punch_EX | 9226 | EX 版 |
| Chou_Tame_Punch | 9277 | 超蓄力 |

### 3.2 Godot 设计

**触发逻辑：**
- 在 IDLE/WALK 状态下**长按 punch 键**超过 0.5 秒 → 进入 CHARGE 状态
- 蓄力期间持续累积蓄力值（0.0 → 1.0）
- 松开 punch 键 → 释放蓄力攻击

**伤害倍率设计：**

| 蓄力等级 | 蓄力时间 | 伤害倍率 | 击退倍率 | hitstop | 说明 |
|----------|----------|----------|----------|---------|------|
| 0（未蓄） | <0.3s | ×1.0 | ×1.0 | 0帧 | 等同普通 Punch_1 |
| 1（半蓄） | 0.3~0.8s | ×1.5 | ×1.5 | 5帧 | 黄光 |
| 2（满蓄） | >0.8s | ×2.0 | ×2.0 | 10帧 | 红光+冲击波 |
| EX（超长） | >2.0s | ×3.0 | ×3.0 | 15帧 | 接 Chou_Tame_Punch |

**SP 消耗：**
- 释放时消耗 SP = 20（半蓄）/ 30（满蓄）/ 50（EX）
- SP 不足时只能释放普通拳

### 3.3 player.gd 新增状态

```gdscript
enum State { IDLE, WALK, PUNCH, KICK, WEAPON, JUMP, HURT, DEAD, CHARGE, DASH, GUARD, DOWN, GET_UP }

# 蓄力状态变量
var charge_level: float = 0.0       # 0.0 ~ 1.0
var charge_hold_time: float = 0.0
var is_charging: bool = false
const CHARGE_MIN_TIME: float = 0.3   # 最小蓄力时间
const CHARGE_MAX_TIME: float = 0.8   # 满蓄力时间
const CHARGE_EX_TIME: float = 2.0    # EX 蓄力时间
```

### 3.4 蓄力输入检测

```gdscript
func _tick_idle(delta: float) -> void:
    velocity.x = 0.0
    var move_input := Input.get_axis("move_left", "move_right")
    if absf(move_input) > 0.1:
        _set_state(State.WALK)
        return

    # === 蓄力检测 ===
    if Input.is_action_pressed("punch"):
        charge_hold_time += delta
        if charge_hold_time >= CHARGE_MIN_TIME:
            is_charging = true
            _set_state(State.CHARGE)
            return

    if Input.is_action_just_pressed("kick"):
        _start_attack("kick")
    elif Input.is_action_just_pressed("weapon"):
        _start_attack("weapon")

func _tick_charge(delta: float) -> void:
    charge_hold_time += delta
    charge_level = clampf(charge_hold_time / CHARGE_MAX_TIME, 0.0, 1.0)
    # 蓄力期间闪白光/黄光
    var glow := 0.5 + charge_level * 0.5
    sprite.modulate = Color(glow, glow, glow)

    # 松开 → 释放
    if Input.is_action_just_released("punch"):
        _release_charge()

func _release_charge() -> void:
    var power_mult: float = 1.0
    var hitstop_mult: float = 1.0
    if charge_hold_time >= CHARGE_EX_TIME:
        power_mult = 3.0
        hitstop_mult = 3.0
    elif charge_level >= 1.0:
        power_mult = 2.0
        hitstop_mult = 2.0
    elif charge_hold_time >= CHARGE_MIN_TIME:
        power_mult = 1.5
        hitstop_mult = 1.5

    # 释放蓄力攻击
    attack_type = "punch"
    attack_data = CombatConfig.get_attack("punch").duplicate()
    attack_data["damage"] *= power_mult
    attack_data["hitstop"] *= hitstop_mult
    attack_elapsed = 0.0
    combo_count = 1
    _set_state(State.PUNCH)
    _setup_hitbox()
    is_charging = false
    charge_hold_time = 0.0
    charge_level = 0.0
```

### 4.4 player.gd DASH 状态

```gdscript
var dash_timer: float = 0.0
var dash_cooldown_timer: float = 0.0
var dash_direction: float = 1.0

func _tick_walk(delta: float) -> void:
    var move_input := Input.get_axis("move_left", "move_right")
    var speed: float = CombatConfig.PLAYER.get("walk_speed", 220.0)
    velocity.x = move_input * speed

    # === 冲刺触发：快速推方向 ===
    if absf(move_input) > 0.9 and dash_cooldown_timer <= 0.0:
        # 检测是否刚从IDLE切入WALK且推满方向
        if not _walk_was_full_speed:
            _dash_buffer = 0.15  # 15帧缓冲
        _walk_was_full_speed = true
    else:
        _walk_was_full_speed = false

    if _dash_buffer > 0.0:
        _dash_buffer -= delta
        if _dash_buffer <= 0.0 and absf(move_input) > 0.9:
            _start_dash(signf(move_input))

    dash_cooldown_timer = maxf(0.0, dash_cooldown_timer - delta)

func _start_dash(dir: float) -> void:
    dash_direction = dir
    dash_timer = CombatConfig.PLAYER.get("dash_duration", 0.35)
    dash_cooldown_timer = CombatConfig.PLAYER.get("dash_cooldown", 0.5)
    facing = dir
    _set_state(State.DASH)

func _tick_dash(delta: float) -> void:
    dash_timer -= delta
    velocity.x = dash_direction * CombatConfig.PLAYER.get("dash_speed", 320.0)

    # 冲刺中攻击
    if Input.is_action_just_pressed("punch"):
        _start_attack("dash_punch")
        return
    elif Input.is_action_just_pressed("kick"):
        _start_attack("dash_kick")
        return

    # 冲刺结束
    if dash_timer <= 0.0:
        if absf(velocity.x) > 1.0:
            _set_state(State.WALK)
        else:
            _set_state(State.IDLE)
```

## 5. 交替加成（P1/P2 交替攻击加成）

### 5.1 Unity 对应

`NKSP.CActorComboControl`（idx=927）：
- `m_PunchComboControl` — 拳连击计数器
- `m_KickComboControl` — 脚连击计数器
- `EnumActionCommmon.PUNCH_COMB_INIT/MAX` / `KICK_COMB_INIT/MAX`

### 5.2 Godot 设计

**核心规则：**
- 玩家连续攻击时，如果**拳→脚**或**脚→拳**交替，则下一击伤害 ×1.2
- 如果连续使用同类型攻击（拳→拳→拳），则不享受交替加成
- 交替加成在连击窗口内有效（与 combo 窗口一致）

**需要追踪的状态：**

| 变量 | 类型 | 说明 |
|------|------|------|
| `last_attack_type` | String | 上一次攻击类型 ("punch" / "kick" / "") |
| `last_attack_time` | float | 上一次攻击时间戳 |
| `alternate_bonus_active` | bool | 当前是否享受交替加成 |
| `alternate_window` | float | 交替判定窗口（默认 1.5s） |

### 5.3 combat_config.gd 新增

### 5.4 player.gd 修改

```gdscript
# 新增状态变量
var last_attack_type: String = ""
var last_attack_time: float = 0.0
var alternate_bonus: float = 1.0    # 当前交替加成倍率

func _start_attack(attack_name: String) -> void:
    # === 交替加成检测 ===
    var now := Time.get_ticks_msec() / 1000.0
    var window: float = CombatConfig.COMBO_SYSTEM.get("alternate_window", 1.5)
    if last_attack_type != "" and last_attack_type != attack_name and (now - last_attack_time) < window:
        alternate_bonus = CombatConfig.COMBO_SYSTEM.get("alternate_bonus_mult", 1.2)
    else:
        alternate_bonus = 1.0

    # 原有逻辑...
    attack_data = CombatConfig.get_attack(attack_name).duplicate()
    attack_data["damage"] *= alternate_bonus
    last_attack_type = attack_name
    last_attack_time = now
```

## 6. 根性起身（残血起身加成）

### 6.1 Unity 对应

| EnumAction | 值 | 说明 |
|------------|-----|------|
| Down_Aomuke | 124 | 倒地（仰面） |
| Down_Utsubuse | 125 | 倒地（俯卧） |
| GetUp | 130 | 起身 |
| GetUp_Roll | 131 | 起身翻滚 |
| Down_Roll | 9413 | 前滚起身 |
| Down_Roll_Back | 9414 | 后滚起身 |
| EnumActionState.REVERSAL | 2 | 反转状态 |

字段：
- `m_GutsHpRate` — 根性 HP 比率
- `m_MaxDamage` — 单次伤害上限（防止被秒）
- `CDamageActionControl.Reversal()` — 起身反转方法

### 6.2 Godot 设计

**核心规则：**
- 当 HP **低于 25%** 时受到致命伤害，触发根性：
  1. 不死亡，HP 锁在 1（或 5% max_hp）
  2. 进入 DOWN 状态（倒地）
  3. 起身时获得 **5 秒攻击 ×1.5 + 霸体（免硬直）** buff
  4. 起身无敌时间 1.0 秒

**buff 参数：**

| 参数 | 值 | 说明 |
|------|-----|------|
| 触发阈值 | HP < 25% max_hp | 根性触发线 |
| 保命 HP | max_hp × 0.05 | 不降到 0 |
| 起身攻击倍率 | ×1.5 | 根性 buff 期间 |
| 起身持续时间 | 5.0s | buff 持续时间 |
| 起身无敌时间 | 1.0s | 起身瞬间无敌 |
| 霸体 | true | buff 期间免硬直 |
| 冷却 | 60.0s | 每次战斗只触发一次 |

## 10. 伤害公式对齐

### 10.1 Unity 伤害链回顾

```
攻击者攻击力 (PUNCH/KICK/WEAPON)
    │
    ▼ CalcDealtDamage()
基础伤害 = 攻击力 × 武器系数 × Buff修正
    │
    ▼ CalcCritical()
是否暴击？→ 是 → 伤害 × 暴击倍率（m_CriticalDamageArray）
    │
    ▼ CalcMagnificateDamage()
伤害放大技能（DAMAGE_SKILL）修正
    │  + 交替加成（×1.2）
    │  + 根性 buff（×1.5）
    │  + 半尸化（×2.0）
    ▼ CalcFinalDamage()
最终伤害 = 基础伤害 - 防御方 TOUGH 减免
         + ResDown/ResStun/ResBreak 抗性
         → 上限 m_MaxDamage
         → 下限 1（根性保命）
```

### 10.2 Godot 当前伤害计算

当前 Godot 的伤害流程：
```gdscript

# enemy.gd take_damage
```

### 10.3 对齐后的 Godot 伤害公式

```gdscript
# 新建 scripts/damage_calculator.gd
class_name DamageCalculator
extends RefCounted

## 伤害计算器 —— 对齐 Unity CDamageCalculator

# 配置
const CRIT_CHANCE_BASE: float = 0.05      # 基础暴击率 5%
const CRIT_DAMAGE_MULT: float = 1.5       # 暴击伤害倍率

# 防御减免曲线：damage_reduction = tough / (tough + K)
# K = 100 时，tough=10 → 9%减免；tough=50 → 33%减免；tough=100 → 50%减免
const DEFENSE_K: float = 100.0

static func calc_dealt_damage(attacker: CharacterBody2D, defender: CharacterBody2D, attack_data: Dictionary) -> Dictionary:
    ## 主计算入口
    var result := {
        "damage": 0.0,
        "is_critical": false,
        "knockback": attack_data.get("knockback", 200.0),
        "hitstop": attack_data.get("hitstop", 0.04),
        "stagger": attack_data.get("stagger", 0.2),
    }

    # 1. 基础伤害
    var base_damage: float = attack_data.get("damage", 10.0)

    # 2. 交替加成
    var alt_mult: float = 1.0
    if attacker.has_method("get_alternate_bonus"):
        alt_mult = attacker.get_alternate_bonus()
    base_damage *= alt_mult

    # 3. 根性 buff
    if attacker.has_method("is_guts_active") and attacker.is_guts_active():
        base_damage *= 1.5

    # 4. 半尸化
    if attacker.has_method("is_half_zombie") and attacker.is_half_zombie():
        base_damage *= 2.0

    # 5. 暴击判定
    var crit_chance: float = CRIT_CHANCE_BASE
    if attacker.has_method("get_crit_chance"):
        crit_chance = attacker.get_crit_chance()
    if randf() < crit_chance:
        result["is_critical"] = true
        base_damage *= CRIT_DAMAGE_MULT

    # 6. 防御减免
    var defender_tough: float = 0.0
    if defender.has_method("get_toughness"):
        defender_tough = defender.get_toughness()
    var reduction: float = defender_tough / (defender_tough + DEFENSE_K)
    var final_damage: float = base_damage * (1.0 - reduction)

    # 7. 半尸化防御降低
    if defender.has_method("is_half_zombie") and defender.is_half_zombie():
        final_damage *= 2.0  # 受伤加深

    # 8. 最小伤害保证
    final_damage = maxf(1.0, final_damage)

    result["damage"] = round(final_damage)
    return result
```

## 12. 风险和注意事项

### 12.1 EnumAction 新增值的风险

| 风险 | 影响 | 缓解方案 |
|------|------|----------|
| EnumAction 有 839 个值，被 ~50 个类引用 | 新增值可能导致反序列化失败 | **Godot 侧自定义状态枚举，不改 DLL** |
| 事件区 9000~10000 已被占用 | 新值不能放在此区间 | 放在 9500+ 区间（SP 区后段）或 Godot 侧独立定义 |
| MAX=10001 | 表长度校验可能失败 | 修改 MAX 值或用 Godot 侧枚举 |

### 12.2 方法体 IL 修改的复杂度

| 修改类型 | 难度 | 推荐方案 |
|----------|------|----------|
| 新增字段到类 | ★★☆ | 可行，dnlib 直接添加 FieldDef |
| 修改构造函数默认值 | ★★☆ | 可行，但数据表不在构造函数里 |
| 新增枚举值 | ★★☆ | 可行，但需同步更新引用表 |
| 注入新逻辑到现有方法 | ★★★★★ | **不推荐**，IL 级操作极易出错 |
| 新增完整方法 | ★★★★ | 需要完整方法体 IL，工作量大 |

### 12.3 推荐策略：Godot 优先，DLL 仅参考

**9 大机制全部在 Godot 侧实现，不修改 DLL：**

| 机制 | Godot 实现方式 | DLL 参考 |
|------|---------------|----------|
| 拳3段/踢2段 | combat_config.gd 数值表 | mstAttackCollisionData 字段结构 |
| 蓄力攻击 | player.gd 新增 CHARGE 状态 | Tame_Punch 三段式结构 |
| 冲刺攻击 | player.gd 新增 DASH 状态 | Dash_Punch/Dash_Kick 触发逻辑 |

| 根性起身 | player.gd 新增 DOWN/GET_UP 状态 | GutsHpRate + Reversal 设计 |
| 合体技 | 双玩家协同触发 | Two_Platoons 动作分段 |

| 半尸化 | player.gd 状态切换 + modulate | Kireru/Overdrive 视觉效果 |

### 12.4 移植顺序建议

```
Phase 1（基础对齐，1~2天）
  ├── 拳3段/踢2段数值对齐（combat_config.gd）
  ├── 帧数据换算（60fps → 秒）
  └── 伤害公式对齐（damage_calculator.gd）

Phase 2（核心新机制，3~5天）
  ├── 蓄力攻击（CHARGE 状态）
  ├── 冲刺攻击（DASH 状态 + dash_punch/kick）
  ├── 格挡系统（GUARD 状态 + guard_gauge）
  └── 倒地/起身（DOWN + GET_UP 状态）

Phase 3（高级机制，3~5天）
  ├── 交替加成（双计数器）
  ├── 根性起身（Guts buff）
  ├── 半尸化（状态切换 + 视觉）
  └── 挡枪（远程格挡）

Phase 4（双人/合体，5~7天）
  └── 合体技（双人协同 + AOE）
```

## 核心结论

1. **9 大机制全部可在 Godot 侧独立实现，无需修改 DLL**。DLL 仅作为设计参考
2. **拳3段/踢2段**：Godot 已有框架，只需在 combat_config.gd 添加 `combo_stages` 逐段数值表
3. **伤害公式**：需新建 `damage_calculator.gd`，对齐 Unity 的四阶段计算链（基础→暴击→放大→最终）
4. **新增状态**：Godot State 枚举从 8 个扩展到 ~15 个（+CHARGE, DASH, GUARD, DOWN, GET_UP, HALF_ZOMBIE）
5. **移植优先级**：Phase 1 基础对齐 → Phase 2 核心新机制 → Phase 3 高级机制 → Phase 4 合体技
6. **最大风险**：IL 级 DLL 修改极易出错，**强烈建议所有逻辑在 Godot GDScript 侧实现**
