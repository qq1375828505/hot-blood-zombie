## 一、Godot 载具 + 可破坏物设计摘要

### 1.1 改装战车（vehicle.gd，195 行）

**核心数值表：**

| 参数 | 值 | 说明 |
|---|---|---|
| `GRAVITY` | 980.0 | 重力（Godot 2D 单位） |
| `MOVE_SPEED` | 180.0 | 驾驶移动速度 |
| `MAX_DURABILITY` | 3 | 耐久度（3 格） |
| `VULCAN_INTERVAL` | 0.08s | 火神机枪射击间隔（约 12.5 发/秒） |
| `CANNON_INTERVAL` | 0.8s | 主炮冷却 |
| `CANNON_AMMO` | 5 | 主炮备弹 |
| `INVINCIBLE_DURATION` | 0.5s | 上下车无敌帧 |
| `BLAST_RADIUS` | 100.0 | 自爆 AOE 半径 |
| 自爆伤害 | 8 | 对范围内敌人造成 8 点伤害 |

**行为逻辑：**

1. **上下车**：玩家走近战车按 crouch 键上车，驾驶员隐藏（`p.visible = false`），玩家输入映射到战车移动；下车时玩家出现在战车侧方，获得 0.5s 无敌帧。
2. **火神机枪**：连发子弹（伤害 1，速度 900），橙色调染，炮管后坐动画，无限弹药，0.08s 间隔。
3. **主炮**：抛物线榴弹（初速度 (±600, -100)），5 发备弹，0.8s 冷却，炮管后坐 + 车身震动。
4. **耐久系统**：受击扣 1 点耐久，红闪 0.15s；耐久归零强制跳车 → 爆炸（放大 1.5x + 淡出）→ AOE 伤害周围敌人。
5. **轮子动画**：行驶时轮子随速度旋转。

### 1.2 可破坏物体（destructible.gd，163 行）

**核心数值表：**

| 参数 | 值 | 说明 |
|---|---|---|
| `DEFAULT_MAX_HITS` | 3 | 普通物体默认破坏次数 |
| `VENDING_MAX_HITS` | 2 | 贩卖机破坏次数（更脆） |
| 每次命中伤害 | 2 | `take_damage(2)` 每次调用 |
| 贩卖机掉落 | 1~2 个 | 随机从补给表选取 |
| 普通掉落 | 1 个 | 按 `item_type` 配置 |

**物体类型与掉落表：**

| 类型 | 最大命中 | 掉落物 |
|---|---|---|
| `generic`（垃圾桶/木箱/轮胎等） | 3 | 按 `item_type` 配置（coin / iron_pipe / tire / trash_lid / ammo） |
| `vending_machine`（自动贩卖机） | 2 | 随机 1~2 个：food_drink / food_onigiri / food_noodles / first_aid |

**行为逻辑：**

1. **受击检测**：子节点 `HitArea(Area2D)` 检测子弹碰撞，命中后调用 `take_damage(2)` 并销毁子弹。
2. **破坏演出**：命中时身体变暗（按剩余耐久比例）+ 左右抖动；破坏时弹出掉落物（上抛后落地弹跳）。
3. **掉落物**：动态创建 `Area2D` + `CollisionShape2D` + 视觉色块，位置偏移错落排列。

## 三、载具系统注入方案

### 3.1 总体判断

**原版无载具系统 → 全新增 MonoBehaviour 组件。**

不能通过扩展现有类实现，因为：
1. 没有 `Vehicle`/`Car`/`Bike` 等任何载具类型
2. `EnumAction`（839 个动作状态）中无骑乘/驾驶动作
3. `CActorNpcControl` 的移动/碰撞系统不支持"乘客"概念

### 3.2 载具组件架构设计

```
ModVehicle (新增 MonoBehaviour)
├── 挂载位置：场景中独立的 GameObject（不挂在 CActor 上）
├── 依赖系统：
│   ├── CObjectControl（物理移动/碰撞，复用其 Rigidbody2D）
│   ├── CInputControl（驾驶员输入转发）
│   ├── CAttackCollision（受击/攻击判定）
│   ├── CDamageCalculator（伤害计算）
│   └── EnumEffect（爆炸/火焰特效播放）
├── 状态：
│   ├── driver: CActorNpcControl（驾驶员引用，null 表示无人）
│   ├── durability: int（耐久度）
│   ├── cannonAmmo: int（主炮弹药）
│   ├── facing: int（朝向 1/-1）
│   └── invincibleTimer: float（无敌帧计时）
└── 核心方法：
    ├── EnterVehicle(CActorNpcControl driver)
    ├── ExitVehicle()
    ├── TakeDamage(int dmg)
    ├── FireVulcan()
    ├── FireCannon()
    └── Explode()
```

### 3.3 上下车与 CActor 的交互方案

**方案：不修改 CActor 内部状态机，而是通过外部组件"覆盖"输入。**

```
玩家站在载具附近 → 按 THROW 键 → EnterVehicle()
  ├── 将 driver 引用设为玩家 CActorNpcControl
  ├── 缓存玩家当前输入状态（m_NavMeshAgent.isStopped = true 停住玩家AI）
  ├── 将玩家 GameObject.SetActive(false) 或设为不可见
  └── 后续 Update 中，载具的移动由自身 Rigidbody2D 处理
       玩家的输入（PUNCH/KICK/JUMP）通过 CInputControl 查询后转发为载具武器触发

下车 → ExitVehicle()
  ├── 恢复玩家 CActorNpcControl
  ├── 玩家位置设为载具侧方偏移
  ├── 给予 0.5s 无敌帧（通过 CActorParameter 的临时 Buff）
  └── driver = null
```

**Harmony Patch 注入点：**

| Patch 目标 | Patch 类型 | 目的 |
|---|---|---|
| `CActorNpcControl.UpdateAiInformation` | Prefix | 驾驶员上车时跳过 AI 更新 |
| `CInputControl.IsKey(EnumKeyID)` | Postfix | 驾驶员上车时，THROW 键触发下车而非投掷 |
| `CActorManager.UpdateActorList` | Postfix | 载具作为独立对象注册到更新列表 |

### 3.4 火神机枪实现方案

火神机枪是无限连发子弹，复用原版子弹系统：

1. **子弹生成**：通过 `CBulletItemControl.Initialize` 创建子弹实例
2. **子弹数据**：使用现有 `mstBulletDataData` 中的低伤害子弹条目，或新增自定义 bullet ID
3. **射击逻辑**：在 `ModVehicle.FixedUpdateRun` 中计时，每 0.08s 调用一次 `FireVulcan()`
4. **子弹方向**：根据 `facing` 设置子弹初速度方向
5. **视觉**：复用 `EnumEffect.Fire` 或自定义枪口闪光

```csharp
// 伪代码：火神机枪射击
void FireVulcan()
{
    vulcanCooldown = VULCAN_INTERVAL;
    // 从对象池取子弹
    var bullet = BulletPool.Get();
    bullet.transform.position = turretFirePoint.position;
    bullet.Initialize(bulletData /* 低伤害高速子弹 */);
    bullet.SetDirection(facing * Vector2.right);
    // 播放枪口火焰特效
    EffectManager.Play(EnumEffect.Fire, turretFirePoint.position);
}
```

### 3.5 主炮实现方案

主炮是抛物线榴弹 + AOE 伤害：

1. **榴弹**：同火神机枪子弹生成方式，但使用抛物线运动（初始速度带 Y 分量）
2. **AOE 伤害**：榴弹命中后，在半径范围内对所有 `CObjectControl` / `CActorNpcControl` 调用 `CAttackCollision.HitFunc`
3. **弹药限制**：`cannonAmmo = 5`，每次射击减 1，归零后不能发射
4. **冷却**：0.8s 冷却计时

```csharp
void FireCannon()
{
    cannonCooldown = CANNON_INTERVAL;
    cannonAmmo--;
    // 生成抛物线榴弹
    var grenade = BulletPool.Get();
    grenade.transform.position = turretFirePoint.position;
    grenade.Initialize(grenadeData /* AOE 榴弹 */);
    grenade.SetVelocity(new Vector2(facing * 600f, -100f));
    // 榴弹命中回调
    grenade.OnHit += OnGrenadeExplode;
}

void OnGrenadeExplode(Vector2 position)
{
    // AOE 伤害：查找半径内所有角色
    var hitResults = Physics2D.OverlapCircleAll(position, BLAST_RADIUS);
    foreach (var hit in hitResults)
    {
        var actor = hit.GetComponent<CActorNpcControl>();
        if (actor != null && actor != driver)
        {
            // 通过 CAttackCollision 施加伤害
            var atkCol = attackCollisionPool.Get();
            atkCol.Init(position, attackData /* AOE 高伤害 */, teamID);
            atkCol.HitFunc(actor);
        }
    }
    // 播放爆炸特效
    EffectManager.Play(EnumEffect.Explosion_Fire, position);
}
```

### 3.6 耐久自爆逻辑

```csharp
void TakeDamage(int dmg)
{
    if (invincibleTimer > 0f || destroyed) return;
    durability--;
    hitFlashTimer = 0.15f;
    // 红闪
```

## 四、可破坏物系统注入方案

### 4.1 总体判断

**原版有 Gimmick 系统和 CObjectControl 基类，但没有"HP + 破坏 + 掉落"一体化的可破坏物组件。**

可破坏物系统应：
1. 复用 `CGimmickCollision` 的受击检测机制（已能响应攻击）
2. 扩展 `CObjectControl` 的物理/渲染能力
3. 新增 `ModDestructibleObject` 组件实现 HP/破坏/掉落逻辑
4. 通过新增 `CModDestructibleGenerator`（仿照 `CItemGenerator`）在关卡中放置

### 4.2 可破坏物基类设计

```
ModDestructibleObject (新增 MonoBehaviour)
├── 挂载位置：继承 CObjectControl 的场景物体 GameObject
├── 依赖系统：
│   ├── CGimmickCollision（受击检测，复用其 SetGimmickAttackData）
│   ├── CObjectControl（物理/渲染基类）
│   ├── CItemGenerator（掉落物生成对接）
│   └── EnumEffect（破坏特效播放）
├── 配置字段：
│   ├── maxHits: int（最大受击次数，默认 3，贩卖机 2）
│   ├── destructibleType: enum（Generic / VendingMachine）
│   ├── dropItemType: EnumItemType[]（掉落物类型表）
│   ├── breakEffect: EnumEffect（破坏时播放的特效）
│   └── damageEffect: EnumEffect（受击时播放的特效）
├── 状态：
│   ├── currentHits: int（已受击次数）
│   └── destroyed: bool
└── 核心方法：
    ├── TakeDamage(int dmg)
    ├── PlayHitEffect()
    ├── OnDestroyed()
    └── SpawnDrops()
```

### 4.3 受击检测对接方案

**复用原版 `CGimmickCollision`：**

原版 `CGimmickCollision` 已有 `m_AttackCollisionID` 和 `SetGimmickAttackData`，说明场景物体受击机制已经存在。可破坏物的对接方式：

```csharp
// 在 ModDestructibleObject.Awake() 中
void Awake()
{
    // 获取同 GameObject 上的 CGimmickCollision
    gimmickCollision = GetComponent<CGimmickCollision>();
    if (gimmickCollision != null)
    {
        // 设置可破坏物的攻击碰撞数据
        // （使用 mstAttackCollisionData 中对应的条目）
        gimmickCollision.SetGimmickAttackData(attackCollisionID);
    }
    // 注册受击回调
    // 通过 Harmony Patch CGimmickCollision.HitFunc 的 Postfix
    // 来调用 ModDestructibleObject.TakeDamage()
}
```

**Harmony Patch 注入点：**

| Patch 目标 | Patch 类型 | 目的 |
|---|---|---|
| `CGimmickCollision.HitFunc` | Postfix | 检测到被攻击时，调用挂载的 `ModDestructibleObject.TakeDamage` |
| `CAttackCollision.HitFunc` | Postfix | 补充子弹类攻击对可破坏物的判定 |

### 4.4 放置/生成方案

**方案 A：新增生成器（推荐）**

仿照 `CItemGenerator` 模式，新增 `CModDestructibleGenerator`：

```
CModDestructibleGenerator : CGeneratorBase
├── 字段：
│   ├── destructiblePrefab: GameObject（可破坏物预制体）
│   ├── destructibleType: EnumDestructibleType
│   ├── dropTable: EnumItemType[]
│   └── spawnOffset: Vector2
└── 方法：
    ├── Awake()
    ├── Clear()
    └── Generate() — 在 m_Transform 位置实例化可破坏物
```

**方案 B：通过关卡数据手动放置**

在 Unity Editor 中（或 mod 加载时），直接在场景中放置带 `ModDestructibleObject` 组件的 GameObject，通过 `WorldScene.Start()` 时初始化。

### 4.5 掉落物对接方案

**复用 `CItemGenerator` 生成道具：**

原版 `CItemGenerator` 已有 `ItemData` 属性和 `_generateCitizen()` 方法，可破坏物破坏后：

```csharp

    /// Patch: CGimmickCollision.HitFunc Postfix
    /// 目的：场景物体被攻击时，通知挂载的 ModDestructibleObject
    /// </summary>
    [HarmonyPatch(typeof(CGimmickCollision), "HitFunc")]
    public static class GimmickCollisionHit_Patch
    {
        static void Postfix(CGimmickCollision __instance)
        {
            var destructible = __instance.GetComponent<ModDestructibleObject>();
            if (destructible != null && !destructible.destroyed)
            {
                // 从攻击碰撞数据获取伤害值
                int damage = __instance.get_attack_Data != null 
                    ? __instance.get_attack_Data.damage 
                    : 1;
                destructible.TakeDamage(damage);
            }
        }
    }
```

## 七、可行性评估

### 7.1 载具系统 — **可行性：中**

| 维度 | 评估 | 说明 |
|---|---|---|
| 原版基础 | 无 | 需全新增 MonoBehaviour，无现成载具框架可扩展 |
| 输入复用 | 高 | `CInputControl` + `EnumKeyID` 18 按键可直接映射上下车/武器 |
| 物理复用 | 中 | `CObjectControl` 的 Rigidbody2D/碰撞可复用，但需自行处理驾驶移动 |
| 伤害复用 | 高 | `CDamageCalculator` + `CAttackCollision` 可直接用于火神机枪/主炮伤害 |
| 特效复用 | 高 | `EnumEffect.Explosion_Fire` + `Fire` 可直接用于枪口闪光和爆炸 |
| AI 交互 | 中 | 需 Harmony Patch 让驾驶员上车时跳过 `CActorNpcControl.UpdateAiInformation` |
| 动画 | 低 | 原版 839 个动作状态中无驾驶动作，载具自身动画（轮子旋转/炮塔转动）需自建 |
| **总体** | **中** | 代码逻辑可写，但需新建完整组件 + 预制体 + 美术资源。主要工作量在物理移动和与 CActor 的解耦 |

### 7.2 可破坏物系统 — **可行性：高**

| 维度 | 评估 | 说明 |
|---|---|---|
| 原版基础 | 有 | `CGimmickCollision` 已有受击检测，`CObjectControl` 是物理基类 |
| 受击对接 | 高 | Harmony Patch `CGimmickCollision.HitFunc` Postfix 即可接入 |
| 特效复用 | 高 | 原版已有 7 种材质破坏特效 + 5 种爆炸特效 |
| 掉落物对接 | 高 | `CItemGenerator` + `EnumItemType` 193 种道具可直接复用 |
| 放置方案 | 高 | 仿照 `CItemGenerator` 新建生成器，或直接场景放置 |
| **总体** | **高** | 原版已有完整的场景物体受击框架，只需新增 HP/破坏/掉落逻辑层 |

### 7.3 综合评估

| 系统 | 可行性 | 预计工作量 | 风险点 |
|---|---|---|---|
| 载具系统 | **中** | 5~8 天 | 与 CActor 的解耦（AI 状态机不支持乘客概念）、物理移动手感调试 |
| 可破坏物系统 | **高** | 2~3 天 | 低风险，主要是配置掉落表和预制体 |
| **合计** | **中-高** | **7~11 天** | 载具是主要工作量，可破坏物相对简单 |

### 7.4 关键风险提示

1. **CActor 状态机不支持"乘客"模式**：原版角色的移动/碰撞完全由 `CActorNpcControl` + NavMesh 驱动，载具需要在外部接管输入并隐藏角色，这种"外部覆盖"方式在边缘情况（如角色被推开/眩晕）可能出 bug。
2. **动画资源缺失**：原版没有载具相关的动画，轮子旋转/炮塔转动只能用程序动画（Tween/协程），视觉表现力有限。
3. **可破坏物受击帧**：`CGimmickCollision` 的受击检测帧（`validFrame`）需要从 `mstAttackCollisionData` 配置中找到合适的条目，如果找不到匹配的，可能需要自定义攻击碰撞数据。
4. **主炮 AOE 伤害范围**：原版 `CAttackCollision` 是基于单个目标的命中判定，AOE 需要手动遍历范围并逐个调用 `HitFunc`，需注意性能（每帧 OverlapCircleAll）。
